# Commit — 내가 고친 것만 커밋

## 왜 이 스킬이 필요한가

에이전트가 `git add .`이나 `git add -A`로 모든 변경사항을 한꺼번에 커밋하면,
사용자가 직접 수정한 파일이나 관련 없는 변경까지 함께 들어간다.
이 스킬은 에이전트가 "내가 건드린 것만 책임진다"는 원칙을 강제한다.

## 흐름

### 1단계: 내가 수정한 파일 식별

현재 대화 세션에서 에이전트가 수정하거나 생성한 파일 목록을 정리한다.
여기서 "내가 수정한 파일"의 범위는:
- 에이전트가 직접 Write, Edit ��구로 수정/생성한 파일
- **에이전트가 투입한 서브 에이전트가 생성/수정한 파일** (서브 에이전트 산출물은 내 작업의 일부다)

대화 컨텍스트를 되짚어서 어떤 파일에 어떤 변경을 했는지 파악한다.

### 2단계: git 상태 확인

`git status`와 `git diff`를 실행해서 현재 작업 트리의 전체 변경사항을 확인한다.
에이전트가 수정한 파일과 그렇지 않은 파일을 구분한다.

### 3단계: 선택적 스테이징

에이전트가 수정한 파일만 `git add <파일경로>`로 개별 스테이징한다.
에이전트가 건드리지 않은 파일은 절대 스테이징하지 않는다.
사용자가 직접 수정한 파일이 같이 잡혀 있어도, 에이전트가 안 건드렸으면 제외한다.

### 4단계: 커밋 메시지 작성

**기본 구조:**
```
<타입>(<범위>): <변경 요약>

<본문 — 무엇을 왜 바꿨는지>

[LESSON: <작업 중 알게 된 교훈이 있다면>]
[FEEDBACK: <사용자로부터 받은 피드백이 있다면>]
```

- 타입: feat, fix, refactor, docs, style, chore 등 conventional commits 따름
- LESSON/FEEDBACK 섹션은 해당 내용이 있을 때만 포함. 없으면 생략.
- LESSON: 이 작업을 하면서 새로 알게 된 것, 다음에 참고할 점
- FEEDBACK: 사용자가 명시적으로 준 피드백, 수정 요청, 방향 전환 등

### 5단계: 커밋 실행

`/commit`을 호출한 시점에서 사용자의 커밋 의사는 이미 확정된 것이다.
다음을 보여주면서 **바로 커밋을 실행한다** (승인을 묻지 않는다):
- 스테이징된 파일 목록
- 커밋 메시지 전문
- 스테이징에서 제외된 변경사항이 있다면 그 목록도 함께

## 주의사항

- `git add .`, `git add -A` 절대 사용 금지.
- 에이전트(+ 서브 에이전트)가 수정하지 않은 파일이 스테이징에 포함되면 안 된다.
- `/commit` 호출 = 커밋 의사 확정. "할까요?" 묻지 않고 바로 실행한다.
- push는 하지 않는다. 사용자가 별도로 요청해야 push한다.
