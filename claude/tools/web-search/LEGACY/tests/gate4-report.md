숫자는 모두 아래 실행에서 나온 값이고, 다른 게이트의 수치를 옮겨 적은 것이 아니다.

- 날짜: 2026-08-11
- 실행 환경: node v22.21.0 · macOS(darwin)
- 실행 명령
  ```
  cd ~/.claude/tools/web-search
  WEBSEARCH_DEPS_DIR=<레포> node tests/gate4.mjs
  ```
- 바깥 접속 없음. 모든 대상은 `fixtures/server.mjs` 가 띄우는 로컬 주소(`http://127.0.0.1:<빈 포트>`)다.
- 결과: **게이트 4 본 항목 5/5 통과**, 게이트 4 전체 57/57 통과, 종료 코드 0.

## G4-1. 워커 둘이 동시에 빌려도 안 겹친다

**어떻게 봤나.** 같은 크롤에 주소 40개를 넣고, **별도 프로세스 두 개**를 같은 순간(공통 시각까지
바쁜 대기)에 출발시켜 각각 `lease(20)` 을 부르게 했다. 게이트 1의 수치를 인용한 것이 아니라
게이트 4 안에서 다시 돌린다.

**관찰값.** 프로세스 A 20건 · B 20건, 겹친 주소 0건, 발급된 표(lease_token) 40개가 모두 다름,
장부의 임대 표시 40건.

**판정: 합격.** 같은 주소도, 같은 표도 두 번 나가지 않았다.

## G4-2. 죽은 워커의 몫은 시간이 지나면 다른 워커에게 간다

**어떻게 봤나.** 임대 시간을 실제로 1초로 둔 크롤에서, 자식 프로세스가 주소 하나를 빌려 쥔 채
`SIGKILL` 로 죽게 했다. 곧바로 남이 가져가려 해 보고, 1.2초를 실제로 기다린 뒤 다시 가져갔다.
그다음 죽은 워커의 옛 표로 결과를 반납해 봤다.

**관찰값.** 종료 신호 `SIGKILL`, 죽은 워커가 쥐고 있었음=true, 시간 전 재배정은
`already_leased` 로 거절, 시간 뒤 재배정 성공(표가 바뀜), 옛 표 보고는 `stale_lease_token` 으로
거절되고 새 표 보고만 1건 반영. 장부에 `lease_expired_requeued` 와 `late_report_rejected` 가 남음.

**판정: 합격.**

## G4-3. 경계를 통과 못 한 링크는 더미에 안 들어간다

**어떻게 봤나.** 허용 도메인은 fixture 호스트 하나, 제외 도메인은 `blocked.test`,
바깥 이동 한도는 0 으로 두고, 목록 쪽을 부모로 삼아 두 링크를 넣었다.

**관찰값.** 더미에 없음=true, 거절 2건, 제외 장부 2건.
제외 도메인 쪽은 `denied_domain` 에 규칙 `["blocked.test"]` 와 부모 주소, 발견 경로 `link:목록` 이 남았고,
바깥 링크 쪽은 `external_hop_exceeded` 에 한도 0 과 부모가 남았다. `status` 에도 2건으로 보인다.

**판정: 합격.** 큐에는 없고, 왜 없는지는 남는다.

## G4-4. 도메인 안전 상한에 닿으면 서고, 어떤 경로가 늘었는지 보고된다

**어떻게 봤나.** 갈림길 fixture(`/maze/<n>` 이 자식 둘을 낳는다)를 **실제로 순회**했다.
`/maze/1` 을 씨앗으로 두고, 큐에서 하나씩 빌려 `fetchOne` 으로 열고, 그 응답에서 `/maze/` 링크만
거둬 부모를 대고 다시 큐에 넣기를 큐가 빌 때까지 반복했다. 경로 형태 상한은 8.

**관찰값(이번 실행).**
- 실제로 연 갈림길 **8쪽**
- 큐에 든 `/maze` 주소 **8개** (상한 8)
- 상한에 걸려 세워 둔 후보 **9건**
- 검토 사유 `path_shape_cap`, 근거 `top_shapes = [{"what":"/maze/*","count":8}]`, 상한 8
- `status.boundary_reviews` 구조에 같은 값이 있고, 완료 판정은 `paused_incomplete`
- 회차 보고서 `cycle-1.md` 본문에
  `경계 검토 127.0.0.1: path_shape_cap (상한 8) · 늘어난 형태 /maze/* 8개`

**판정: 합격.** 조용히 자르지 않고 섰으며, 무엇이 얼마나 늘었는지가 값으로 남는다.

## G4-5. status 가 자주 나온 도메인·낱말·막힌 곳을 요약한다

**어떻게 봤나.** MCP 서버를 자식 프로세스로 띄워 `initialize` 뒤 `status`(크롤 둘)와
`evidence` 를 `tools/call` 로 실제 왕복하고, 돌아온 본문을 읽었다.

**관찰값(MCP 본문).**
```
자주 나온 도메인: 127.0.0.1(1)
자주 나온 낱말: 디자인(12) · 청첩장(2) · 목록(1) · 구조만(1) · 12개(1)
사람 확인 대기 1건
빈칸 표:
  country: 빈칸 [US] · 찾음 [KR]
  vendor_type: 빈칸 [mcheong] · 찾음 [없음] · 표 없는 도메인 1곳
경계 검토 127.0.0.1: path_shape_cap(상한 8) · 형태 /maze/* 8개
안 들인 것 2건 · 나중에 풀린 것 0건   (evidence: excluded)
```

**판정: 합격.** 개수만이 아니라 형태·상한·빈칸이 값으로 나온다.
