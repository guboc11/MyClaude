# 나가는 길은 하나다 — HTTP·DNS·redirect·robots 안전 계층

태스크 `2026-08-12-web-search-MCP-v2-rebuild#25` · 근거 계획: `_PLAN/2026-08-11-web-search-mcp/PLAN.md` 5-3·5-4

```
node tests/network/verify.mjs          # 전부 검사 (exit 0 이면 통과)
node tests/network/verify.mjs --json
```

모든 요청은 이 시험이 띄운 127.0.0.1 fixture 로만 간다. 마지막 항목들이 그것을 판정한다.

## 검사한 곳과 붙은 곳이 같아야 한다

검사와 연결이 갈라지면 검사는 아무 의미가 없다. 이름을 검사하고 나서 연결할 때 다시 풀면,
그 사이에 DNS 가 바뀌어(rebinding) 검사한 곳이 아닌 데로 나간다.

그래서 **검사에서 얻은 IP 로 소켓을 못 박는다.** 다만 host 를 IP 로 바꿔치지 않는다 —
그러면 Host 머리와 TLS SNI 가 IP 가 되어 가상 호스트가 엉키고 인증서 검증이 깨진다.
대신 연결 직전의 이름 풀이(`lookup`)만 갈아 끼운다. 이름은 그대로 두고 **어디로 붙을지만** 정한다.

N5 가 이것을 서버 쪽에서 확인한다. `http://fixture.test:PORT/...` 를 부르면 fixture 서버가 받은
Host 머리는 `fixture.test:PORT` 다 — IP 가 아니다. N6 은 그 요청 동안 이름 풀이가 **1회뿐**이었음을
센다. 검사와 연결 사이에 다시 풀지 않았다는 뜻이다.

붙은 뒤에도 따로 확인한다. 소켓의 `remoteAddress` 가 그 홉의 허용 집합에 없으면 즉시 끊고
`connect/remote_address_mismatch` 로 남긴다. 살려 둔 연결(keep-alive)을 물려받았을 때도 같은 확인을
받는다 — 앞 요청에서 안전했다는 것이 지금도 안전하다는 뜻은 아니다.

## 홉마다 처음부터 다시

앞 홉이 안전했다는 것은 다음 홉에 대해 아무것도 말해 주지 않는다. 리다이렉트를 따라갈 때마다
URL·규약·DNS 검사가 처음부터 다시 돈다. 앞 홉의 허용 집합을 물려받지 않는다.

| 시험 | 무엇을 걸었나 | 결과 |
|---|---|---|
| N12 | 안전한 곳 → `http://10.0.0.5/x` | `policy/ip_private` · 둘째 홉에 **연결한 적 없음** |
| N13 | 안전한 곳 → `http://127.0.0.1:9/x` | `policy/ip_loopback` — 같은 루프백이라도 허용 목록 밖 포트다 |
| N14 | 안전한 곳 → `ftp://example.com/x` | `url/url_scheme` |
| N15 | 자기 자신으로 되돌아가는 리다이렉트 | `redirect/redirect_loop` |
| N16 | 3홉 체인에 상한 1홉 | `redirect/too_many_redirects` |
| N17 | 3xx 인데 Location 없음 | `redirect/redirect_no_location` |

## 상한

| 이름 | 기본값 | 무엇을 막나 |
|---|---|---|
| connect | 5초 | 붙지 않는 곳에 매달려 있기 |
| headers | 10초 | 붙었는데 응답이 안 오기 |
| body | 15초 | 본문이 오다 마는 것 |
| overall | 30초 | 위 셋을 다 지켜도 전체가 길어지는 것 |
| redirect | 5홉 | 끝없는 되돌림 |
| 크기 | 10MB | 거대한 본문·압축 폭탄 |

N21 이 상한이 **진짜로 도는지**와 **늘 걸리는 것은 아닌지**를 함께 본다 — 같은 2초짜리 쪽이
600ms 상한에서는 걸리고 4,000ms 상한에서는 통과한다. 하나만 보면 "언제나 실패하는 시험" 과
구분되지 않는다.

크기 상한은 자르되 실패로 만들지 않는다(N24). 12MB 쪽을 1MB 에서 자르고 `truncated: true` 로
표시한다. 압축을 풀기 전 크기도 함께 막아서, 작은 파일이 거대하게 부푸는 것을 미리 끊는다.

## 쿠키·인증은 오가지 않는다

보내는 쪽에서 `cookie`·`authorization`·`proxy-authorization` 을 지운다. 부른 쪽이 넣어도 지운다.
받는 쪽에서는 돌려주는 머리 목록에 `set-cookie` 가 아예 없다 — 어딘가에 적히면 그게 곧 세션 보관이다.

N18 이 양쪽을 겹쳐 본다. 쿠키를 심고 다른 곳으로 보내는 fixture 를 부르면, 돌려받은 머리에
`set-cookie` 가 없고 따라간 요청에도 `cookie` 가 없다.

## robots 는 명시적 차단만

`robots.txt` 가 없거나(404) 못 읽으면 **막힌 것이 아니다.** 규격은 5xx 를 전부 금지로 읽으라고
하지만, 그러면 상대가 잠깐 흔들리는 것만으로 조사가 통째로 멈추면서 왜 멈췄는지는 아무도 모른다.
여기서는 404 를 "규칙 없음", 그 밖의 실패를 "모름" 으로 그대로 남기고 나간다(N30).

막혔을 때는 `robots_disallowed` 라는 이름으로 관찰만 남긴다. 판정이 아니다 — 막힌 줄을 그대로
적고, 이 항목을 어떻게 할지는 에이전트가 정한다.

`lib/robots.mjs` 에는 네트워크 코드가 없다. 가져오는 일은 부른 쪽이 넘겨준 fetcher 가 한다 —
그래야 robots 도 다른 요청과 똑같은 검사·고정·상한을 받는다.

## 완료 조건 실측

위험한 목적지 7종(사설망 리다이렉트, 허용 목록 밖 루프백 포트, ftp 규약, `10.0.0.5`,
클라우드 메타데이터 주소 `169.254.169.254`, `[::1]`, 사용자명이 든 URL)을 모두 거절했고,
**그중 연결이 성립한 홉은 0개**다. 시험 전체에서 못을 박은 곳은 `127.0.0.1` 뿐이다.
실패 7건 모두 단계와 코드가 있다:

```
policy/ip_private · policy/ip_loopback · url/url_scheme · policy/ip_private
policy/ip_link_local · policy/ip_loopback · url/url_userinfo
```

시험 문이 없으면 아예 못 나간다(N4). fixture 허용 목록 없이 부르면 `policy/ip_loopback` 이고,
**서버가 받은 요청은 0건**이다 — 막았다는 우리 말이 아니라 맞은 쪽의 기록이다.

## 만드는 동안 실제로 걸린 것

**IPv6 리터럴이 IP 분류를 통째로 건너뛰고 있었다.** `new URL('http://[::1]/').hostname` 은 대괄호를
포함한 `[::1]` 을 돌려준다. `net.isIP('[::1]')` 은 0 이라, 목적지 검사가 "주소를 그대로 쓴 경우"
갈래를 타지 못하고 이름 풀이로 흘러갔다. 마침 `[::1]` 이라는 이름이 DNS 에 없어서 `dns_ENOTFOUND`
로 막혔을 뿐, `ip_loopback` 으로 막힌 것이 아니었다. **IPv6 사설·루프백 주소에는 IP 분류가 한 번도
적용되지 않고 있었다는 뜻이다.**

더 나쁜 것은 이것을 잡았어야 할 시험이 통과하고 있었다는 점이다. `tests/unit/url.mjs` 의 U15 는
`blocked_hosts` 에 `http://[::1]/x` 를 넣어 두고도 "막혔는가" 만 봤다. 왜 막혔는지를 안 보니
이름 풀이 실패로도 통과했다. `normalizeUrl` 이 대괄호를 벗기도록 고치고, U15 는 **주소를 그대로 적은
곳은 반드시 `ip_*` 사유로 막혀야 한다**로 바꿨다. 지금은 `[::1]→ip_loopback` 이 찍힌다.

**`cookie: undefined` 를 머리에 넣으면 Node 가 거절한다.** 쿠키를 막겠다고 `undefined` 로 덮어썼는데
`Invalid value "undefined" for header "cookie"` 로 모든 요청이 죽었다. 값으로 지우는 것이 아니라
키를 빼야 한다. 지금은 내보내는 머리를 만든 뒤 금지 목록을 한 번 더 훑어 지운다.

**`lookup` 콜백은 `options.all` 을 봐야 한다.** Node 22 의 autoSelectFamily 는 배열
(`[{address, family}]`)을 기대하는데 단일 인자로 답해서 `Invalid IP address: undefined` 가 났다.

**살려 둔 소켓에 `on('connect')` 를 걸면 듣는 이가 쌓인다.** 요청마다 하나씩 붙어
`MaxListenersExceededWarning` 이 났다. `once` 로 바꾸고, 이미 붙어 있는 소켓은 바로 확인하도록 갈랐다.

## 지금 알려진 한계

- **TLS 는 인증서 검증까지 겨루지 못했다.** 로컬 fixture 가 평문 HTTP 라 handshake 실패 경로만
  코드에 있고 시험은 없다. 인증서 이름 검증은 Node 의 기본 `checkServerIdentity` 에 맡기며,
  host 를 IP 로 바꾸지 않고 `lookup` 만 갈아 끼운 덕에 그 기본 동작이 그대로 살아 있다 —
  **그렇게 설계했다는 것이지 실측했다는 뜻은 아니다.** SNI 도 같은 이유로 코드 근거뿐이다.
- **속도 제한과 아직 이어지지 않았다.** `withPace`(#24)와 `fetchSafely`(#25)는 따로 있다.
  둘을 묶는 것은 수집 조정 계층(#28)이고, 게이트 3 이 "요청 전에 예약했는가" 를 실측한다.
- **robots 기억은 프로세스 안에서만 산다.** 파일로 남기지 않는다 — 오래된 사본으로 막거나
  뚫는 것은 둘 다 잘못이다. 프로세스가 여럿이면 도메인마다 여러 번 가져온다.
- **fixture 문이 이름까지 넓어졌다.** 풀린 주소가 **전부** 허용 목록에 그 포트로 있을 때만 열린다.
  DNS 가 새로 허락하는 것은 없다 — argv 로 이미 허락한 곳을 이름으로 부를 수 있게 할 뿐이다.
  Host 머리 보존을 이름으로 증명하려고 넓혔고, `tests/fixtures` 의 F16 이 경계 셋(포트 다름,
  목록 밖 주소 섞임, 이름으로 맞음)을 함께 지킨다.
