## 한 번에 다시 돌리는 법

```
node tests/gate2.mjs           # 전부 실행하고 판정 (exit 0 이면 통과)
node tests/gate2.mjs --json
```

일꾼은 [gate2-worker.mjs](../gate2-worker.mjs) 다. 하나하나가 `server.mjs` 를 자식으로 띄운
**독립 MCP 클라이언트**이고, 버튼으로만 말한다 — 내부 함수를 직접 부르면 경계를 건너뛴 시험이 된다.
같은 순간에 임계 구역으로 들어가도록 공통 시작 시각까지 바쁜 대기를 건다. 이 배리어가 없으면
프로세스 시작 지연 때문에 앞선 쪽이 이미 끝나 있어 경합 자체가 생기지 않는다.

시각은 DB 의 `lease_expires_at` 을 앞당겨 흐르게 한다. 시스템 시계를 만지지 않는다.

### 실제 수치

**동시 임대.** 프로세스 10개가 같은 순간에 100개씩 요청해 10/10 이 성공했고 오류·대기 한도 초과가
0이다. 일꾼이 보고한 합 1,000 = DB 의 `leased` 1,000이고, 한 항목을 두 임대가 잡은 경우가 0,
서로 다른 임대가 정확히 10개다. 작업 파일 1,000줄과 DB 의 임대 배정을 항목별로 맞춰 보니 어긋남 0이다.

**강제 종료 복구.** 임대를 쥔 워커 둘을 SIGKILL 하고 그 임대의 만료 시각을 앞당긴 뒤 새 워커가
`next` 를 부르니 100건을 받았고, 그 100건이 **모두 죽은 워커가 쥐고 있던 것**이었다. 살아 있는
임대 8개는 건드려지지 않았고 중복도 0이다.

**보고 규약.** 같은 report 를 두 번 보내면 둘 다 "반영 3" 을 돌려주지만 판정 행은 3건, `reports`
기록은 1건, `done` 은 3건이다 — 두 번째는 아무것도 바꾸지 않는다. 반납된 임대에 **다른** 보고를
보내면 `stale_lease` 로 거절되고 판정 행이 3→3 그대로다. 다른 workspace 에 같은 `lease_id` 로
보내도 거절되고 저쪽 판정은 0건이다.

**재시도.** `done` 3건을 되돌리니 `attempts` 지문(SHA-256)이 동일하고 판정 3→3 그대로이며
`retries` 이력이 3건 쌓였다. 없는 번호는 `not_in_this_workspace` 로 거절된다.

**결정성.** 게이트 2를 세 번 연속 돌려 모두 exit 0 이고, 실행 전후로 남은 `server.mjs` 프로세스 수가
변하지 않았다(5→5, 이 다섯은 이 세션 밖에서 이미 돌던 것이다).

## 만드는 동안 실제로 걸린 것

**보고의 멱등 확인이 임대 확인보다 뒤에 있었다.** 첫 보고가 성공하면 그 임대는 풀린다. 그 뒤 같은
요청이 다시 오면(응답을 못 받아 다시 보내는 흔한 경우) 임대부터 보기 때문에 "만료된 임대" 로
거절됐다. 게이트 2를 처음 돌렸을 때 여기서 터졌다. 순서를 뒤집어 **이미 받아 둔 요청은 같은 답을
주고, 처음 보는 요청만 임대 검사를 받게** 했다. 늦은 보고를 막는 성질은 그대로다 — 처음 보는
요청은 여전히 죽은 임대에서 거절된다. 게이트의 해당 항목도 "같은 보고"에서 "다른 보고"로 바꿨다.
같은 보고가 같은 답을 주는 것은 잘못이 아니라 계약이기 때문이다.

**서버가 부른 쪽이 죽어도 살아남았다.** 워커를 SIGKILL 하면 그 워커가 띄운 `server.mjs` 가 고아로
남았다. stdin 이 닫히면 함께 끝나도록 고쳤다. 그러지 않으면 강제 종료 시험을 돌릴 때마다 서버가
하나씩 쌓인다.

## 지금 알려진 한계

- **`collect` 가 없다.** 그래서 이 게이트는 수집 기록(`attempts`)을 손으로 만들어 `report` 의 앞길만
  열었다. 진짜 수집·산출물은 #26~#31 이 만들고 게이트 3이 실측한다. 지금 `report` 가 "수집 없는
  항목은 done 으로 안 만든다" 를 지키는 것은 확인했지만, 진짜 collect 와 이어 붙인 적은 없다.
- **시간은 DB 를 고쳐 흐르게 했다.** 실제 60분 만료를 기다린 것이 아니다. 만료 판정 자체는 단위
  시험이 경계 시각(만료 1ms 전·만료 시각·만료 후)으로 따로 본다.
- **`search`·`map_domain`·`collect`·`export` 넷이 없다.** 계약 시험은 그 넷에서만 실패한다.
- **`search` 는 미완료로 남는다** — 무키 공급자를 찾지 못했다([decision.md](../spikes/search-provider/decision.md)).
- **네트워크로 나가는 코드는 아직 없다.** `lib/network-policy.mjs` 는 판정만 하고, 그 판정으로 실제
  연결을 고정하는 일은 #25 가 한다.
