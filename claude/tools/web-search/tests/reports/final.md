## 못 채운 조건 하나

**P9 — "직접 검색 버튼은 검증된 검색 방식 하나가 실제로 작동해야 완료로 표시한다."**

키 없이 쓸 수 있는 검색 공급자 후보 아홉 곳을 실측했고 **살아남은 곳이 0** 이다.
여섯 곳은 robots 가 검색 경로를 막았고, 한 곳은 사람 확인 화면이 떴고, 두 곳은 애초에
다른 기능이었고, 세 곳은 이용 조건에 걸렸다(겹침 있음). 사용자가 유료 API 를 쓰지 않기로
확정했으므로 이 조건은 **방침상 채울 수 없다.**

- 근거: [decision.md](../spikes/search-provider/decision.md) · [gate5.md](gate5.md)
- 관련 태스크: `#36`(공급자 adapter) · `#37`(search 실행·원문) · `#38`(게이트 5)
  — 셋 다 "결론이 확정·문서화·검증됐다" 는 뜻으로 닫았지, "구현했다" 는 뜻이 아니다.
- 다시 보려면: `node tests/gate5.mjs` · `node tests/spikes/search-provider/verify.mjs`

**대신 가는 길은 검증됐다.** 에이전트가 자기 `WebSearch` 로 찾아 `add_urls` 에
`source_kind="search"`, `source_value=검색어` 로 넣는다. 게이트 5 에서 5개 언어 검색어 10개로,
시나리오 A 에서 5개 언어 검색어 22개로 실제로 돌렸다. 되짚어지는 것은 **검색어까지**이고
순위·제목·설명 원문·언어는 남지 않는다.

## 실전에서만 드러난 결함 다섯

시험은 다섯 번 다 통과하고 있었다.

1. **브라우저가 진짜 사이트를 한 장도 못 열었다.** 속도 예약을 요청마다 걸어서, 한 페이지의
   그림·글꼴 수십 개가 각각 10초를 기다리다 이동이 먼저 죽었다. 게이트 3 은 간격을 1밀리초로
   낮춰 돌리므로 **드러날 수가 없었다.**
2. **예약을 이동에만 걸었더니 이번엔 기다림이 이동 시간을 먹었다.** 워커 셋이 같은 도메인에
   줄을 서자 22쪽 중 21쪽이 30초 초과로 죽었다. 기다림을 이동 **밖**으로 옮겨 고쳤다.
   한 자리를 세 번 고쳤고, 두 번 다 "실제로 끝까지 안 가 봐서" 못 봤다.
3. **근거를 대라는 규칙을 버튼만으로는 지킬 수 없었다.** `report` 가 요구하는 `artifact_id` 가
   수집 요약에 없었다. 장부를 직접 열지 않는 한 알 길이 없었다.
4. **오류 화면 판별이 71쪽 중 68쪽에 붙었다.** 한 사이트가 숨겨 둔 안내 문구를 잡은 것이다.
   96%에 붙는 표시는 아무것도 알려 주지 않는다. 범위를 좁히고, "내용이 없다" 는 다른 사실에
   `thin_text` 라는 다른 이름을 줬다.
5. **MCP 가 죽었는데 부른 쪽이 한 시간을 기다릴 참이었다.** 시나리오 C 가 21분 멈춰 있었고
   SUPERVISOR 가 관찰해 알려 주었다. 자식이 끝나면 기다리던 요청을 그 자리에서 깨우도록 고쳤다.

**같은 부류의 시험 결함도 여섯 번 나왔다** — 통과했지만 아무것도 재지 못했거나, 재는 대상이
아니라 그날의 우연을 붙들고 있던 항목들이다.

| | 무엇이 잘못됐나 |
|---|---|
| G0-5 | 원인 오진 — 셈이 맞아떨어져 다른 곳을 짚었다 |
| G1-13 | 시점 고정 — 그날의 집합을 기대했다 |
| 게이트 3 | 조건을 만들지 않고 **믿었다**(playwright 없음) |
| G4-8 | 증명할 오류가 아예 없었다 |
| G0-5 | 경로 단정 — spike 를 옮기자 옛 경로를 기대한 채 남았다 |
| 게이트 1·2 | **날짜 단정** — workspace 이름을 어제 날짜로 지어내다가 자정을 넘기자 없는 폴더를 찾았다(2026-08-13) |

마지막 것은 SUPERVISOR 가 날이 바뀐 뒤 재검증하다 잡았다. 고침은 같다 —
**만든 쪽이 돌려준 이름을 쓰고, 이름은 모양만 본다.** 게이트 7 과 최종 게이트도 같은 이유로
실전 workspace 를 날짜가 아니라 주제 이름으로 찾도록 바꿨다.

그래서 게이트 4 부터는 판정 문구에 **실제로 본 수치**를 적는다.

## 이 도구가 하지 않는 것

계획서 1-3 의 목록을 그대로 지켰다. 아래는 코드로 막혀 있거나 애초에 없다.

- 청첩장·상품·업체인지 **자동 판단하지 않는다.** 이름표는 사람이 붙인다.
- **상품 카드 자동 인식이 없다.** 목록·상세 자동 분류도 없다.
- **숨은 재귀 크롤이 없다.** 지도는 확인한 범위만 만들고, 넓히려면 에이전트가 다시 부른다
  (게이트 4: 발견 29곳 중 지도가 방문한 곳 **0곳**, 맞은 쪽 기록으로 확인).
- **조사 완료를 선언하지 않는다.** `workspace_drained` 는 "넣은 일에 대기·임대가 없다" 뿐이다.
- **여러 검색 공급자를 동시에 지원하지 않는다.** 하나도 없다(P9).
- **로그인 세션·쿠키를 저장하지 않는다.** 실제 크롬 프로필도 쓰지 않는다.
- **차단을 우회하지 않는다.** CAPTCHA 를 풀지 않고, 막힌 곳은 막혔다고 적는다.
- **에이전트를 만들거나 배치하지 않는다.**
- 불확실한 페이지의 자료를 **통째로 버리지 않는다.** 관찰로 표시하고 원본은 남긴다.

## 남은 한계

- **`search` 버튼이 없다.** 공개 버튼은 아홉이다. 계약은 열이고 그 차이가 P9 다.
- **되짚기는 검색어까지다.** 순위·제목·설명 원문·언어는 남지 않는다(게이트 5 G5-B2).
- **브라우저 수집에는 부른 프로젝트에 playwright 가 있어야 한다.** 이 도구 폴더에는 없다.
  등록의 `WEBSEARCH_DEPS_DIR` 로 그 자리를 알려 준다.
- **한 도메인에서는 워커를 늘려도 안 빨라진다.** 예약이 도메인 단위라 같은 줄에 선다.
  실측 쪽당 12.4초.
- **화면 갈무리가 무겁다.** 한 장에 1.5MB 안팎. 큰 조사에서는 대상을 좁혀야 한다.
- **안 끝난 실행 3건이 장부에 남아 있다.** 강제 종료 연습과 시나리오 B 에서 생긴 것이고,
  지우지 않았다 — 언제 무엇을 하려다 끊겼는지가 그 줄에만 남아 있다.
- **작업대 세 곳이 dibang 레포 안에 335MB 로 있다.** gitignore 안이라 커밋되지 않는다.
- **시나리오 B 의 첫 판정 66건이 성급했다.** 주소만 보고 "상품" 이라 적었다. 두 번째 판정이
  함께 남아 있어 읽는 사람이 그 어긋남을 본다.
