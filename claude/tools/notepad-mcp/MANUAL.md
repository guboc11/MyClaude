# notepad-mcp MANUAL

사람용 메모장 도구 8종 — 적기(note_add / note_add_conversation) · 주제 노트(note_new_topic / note_append) · 꺼내기(note_list / note_read / note_search) · 원문(note_source).
관할 공간: `.claude/notepad/` (gitignore 대상 — 개인 기록).
설계 원천은 `.claude/tools/notepad-mcp/DESIGN.md`. 사용 장면은 같은 폴더 `USAGE.md`.

## 노트는 두 종류다

| | 날짜 노트 | 주제 노트 |
|---|---|---|
| 자리 | `.claude/notepad/{YYYY-MM}/` 월 폴더 안 | `.claude/notepad/` 루트에 바로 |
| 이름 | `{YYYY-MM-DD-HHMM}.md` — 이름이 곧 시각 | `{만든 날}-{주제}.md` — 이름이 곧 정체 |
| 성격 | **그 순간을 찍고 끝난다.** 한 장이 한 순간 | **줄이 계속 쌓인다.** 한 장이 한 주제 |
| 만들기 | `note_add` / `note_add_conversation` | `note_new_topic` |
| 덧붙이기 | **안 된다.** 찍힌 순간에 뒤늦게 덧대지 않는다 | `note_append` |
| 날짜의 뜻 | 적은 시각 | **만든 날로 고정.** 줄이 쌓여도 파일명은 안 바뀐다 |

- 목록(`note_list`)은 **주제 노트 묶음이 위, 날짜 노트 묶음이 아래**로 나뉘어 나온다.
- **주제별 하위 폴더는 아직 만들지 않는다.** 루트에 쌓아두고 많아지면 그때 묶는다 (2026-08-05 결정).

## 프레임워크 (처음 쓰는 에이전트는 여기부터)

- **주인은 사람, 에이전트는 관리인이다.** 노트는 사용자의 기록이고, 클로드는 받아적고 꺼내줄 뿐이다.
- **MEMORY.md와 갈라지는 지점**: 메모리는 매 세션 상주해 사고를 물들이지만, 노트는 **평소 컨텍스트 0**이고 부를 때만 들어온다.
  → "저장은 하고 싶은데 클로드가 계속 그 맥락에 사로잡히는 건 싫은 것"이 노트의 자리다.
- **어휘가 도구를 가른다**: "기억해줘" → 메모리 / **"노트에 적어줘·메모해줘" → notepad**.
- **적을 때 해석하지 않고, 꺼낼 때 해석한다.** 이것이 이 도구의 한 줄 요약이다.
  - 적을 때: 제목·키워드·태그를 **만들지 않는다**. 그런 칸이 아예 없다.
  - 꺼낼 때: 묶고 요약하고 판단해도 된다. 단 **그 해석을 파일에 저장하지 않는다.**
- **표시 없는 텍스트는 절대 클로드가 쓴 것이 아니다.** 클로드가 보탠 덩어리엔 반드시 구분선이 붙는다.
- **꺼내기는 두 걸음**: `note_list`로 훑고 → 고른 것만 `note_read`·`note_source`로 펼친다.

## 형식

- 무의존성 Node stdio JSON-RPC 서버 (prototype-mcp·task-mcp와 같은 골격). 외부 패키지 0, MCP SDK 미사용.
- **레포 내장**: `.claude/tools/notepad-mcp/server.mjs` + `.mcp.json` 등록 — 클론하면 팀원 클로드에 자동 연결.
- 읽기: 메모 파일 실시간 (**캐시 없음** — 사용자가 손으로 고친 내용이 즉시 반영된다).
- **수정·삭제 도구 없음** — md 파일이라 사용자가 직접 고치고, 한 번 적힌 것은 지우지 않는다.
  `note_append`가 생겼지만 그건 **붙이기**지 고치기가 아니다. 이미 적힌 줄은 여전히 손대지 못한다.

## 메모 한 장

```markdown
---
created: 2026-07-28 15:44
context: notepad MCP 설계 대화 중
transcript: 21006ad2-76fa-43c1-bc7b-2a67fd9f67a4.jsonl
lines: 381
---

mcp 서버가 대화 원문 찾아주는 버튼이 있어야지
아 그래 내가 yazi 켜서 읽기도 편해야해
```

frontmatter는 **네 칸 고정**. 값이 비어도 칸은 사라지지 않는다.
그중 **에이전트가 채우는 것은 `context` 하나뿐**이고, 나머지 셋은 서버가 자동으로 채운다.

| 칸 | 내용 |
|---|---|
| `created` | 서버가 채움 |
| `context` | **에이전트가 채움.** "○○ 대화 중" — 정황만. 의미 주장 금지 |
| `transcript` | 서버가 채움. `CLAUDE_CODE_SESSION_ID` 기준 (추정하지 않는다) |
| `lines` | 서버가 채움. 단일(`381`) 또는 범위(`381-399`) |

## 본문 덩어리 3종

| 덩어리 | 표시 | 정체 |
|---|---|---|
| 사용자 말 | **없음** | 준 텍스트 그대로 |
| 대화에서 인용 | `-------------------- 사용자 (381줄) --------------------` | 실제로 오간 말 |
| 클로드가 새로 쓴 것 | `-------------------- 클로드 해석 --------------------` | 지시받아 지금 쓴 것 |

**줄 번호 유무가 인용과 창작을 가른다.** 번호가 있으면 되짚어 확인할 수 있는 실제 발언이고, 없으면 클로드가 지어낸 문장이다.
구분선은 **ASCII 하이픈 20개** — 사용자가 직접 편집할 때 키보드로 칠 수 있어야 하기 때문이다.

## 도구

### note_add — 사용자가 준 텍스트를 그대로 적기

| 인자 | 필수 | 설명 |
|---|---|---|
| `body` | | 사용자가 준 텍스트. **한 글자도 고치지 않는다.** 없으면 빈 종이 |
| `context` | | "○○ 대화 중" 정황 한 줄 |
| `agent_note` | | 사용자가 **명시적으로 요청했을 때만**. 평가 아닌 사실만 |

반환: `적었습니다 — 2026-07-28-1544` + 파일 경로.
저장 뒤에는 **영수증 한 줄만 말하고 대화를 이어간다.** 길게 요약하면 이 도구의 존재 이유가 무너진다.

### note_add_conversation — 줄 범위를 파싱해 대화 메모

| 인자 | 필수 | 설명 |
|---|---|---|
| `from` / `to` | O | 줄 범위(1부터, `to` 포함) |
| `context` | | 정황 한 줄 |
| `include_thinking` | | 클로드 사고 과정 포함. 기본 false |

에이전트가 하는 판단은 **범위 하나뿐**이다. 누락보다 과잉 — 좁게 잡았어도 나중에 `note_source`로 넓혀 읽을 수 있다.
줄 번호는 `note_search`의 `deep` 결과나 `note_source` 출력에서 얻는다.

걸러지는 것: 서브에이전트(`isSidechain`) · `user`/`assistant` 아닌 사건줄 · 도구 결과만 든 메시지 · `<system-reminder>` 삽입물.
도구 호출은 `[도구: Bash]` 한 줄로 축약된다.

### note_new_topic — 주제 노트 새로 만들기

| 인자 | 필수 | 설명 |
|---|---|---|
| `topic` | O | 주제 이름. 한글·영문 자유. **날짜는 서버가 앞에 붙이므로 적지 않는다** |
| `body` | | 첫 내용. 그대로 넣는다. 없으면 빈 주제 노트 |
| `context` | | 정황 한 줄 |

반환: `만들었습니다 — 2026-08-05-표현교정` + 파일 경로.

**거부되는 것** — 조용히 고쳐서 만들지 않는다. 부른 이름과 다른 파일이 생기는 쪽이 더 나쁘다.

| 입력 | 결과 |
|---|---|
| 같은 이름이 이미 있음 | `이미 있는 주제 노트입니다` — 덮어쓰지도, 뒤에 번호를 붙이지도 않는다 |
| 앞뒤 공백 (`" 표현교정"`) | `주제 이름 앞뒤에 공백이 있습니다` — **이름 안의 공백은 쓸 수 있다** |
| `/` `\` `:` `*` `?` `"` `<` `>` `\|` · 제어문자 | `쓸 수 없는 글자가 있습니다` |
| `..` 포함 · `.` 로 시작 · 빈 이름 | 각각 명확한 오류 |

### note_append — 주제 노트 끝에 한 줄 잇기

| 인자 | 필수 | 설명 |
|---|---|---|
| `id` | O | 주제 노트 id (예 `2026-08-05-표현교정`) |
| `body` | O | 붙일 텍스트 **한 줄**. 다듬지 않고 그대로 |

반환: `붙였습니다 — 2026-08-05-표현교정` (영수증 한 줄).

붙은 줄 끝에 **`(MM-DD HH:MM)`** 으로 언제 들어왔는지 남는다.

```
피하기: "패널이 갈립니다" → 권장: "여기랑 옆 패널은 별개입니다"  (08-05 09:22)
```

**고치는 도구가 아니다.** 파일 끝에만 잇고 frontmatter와 기존 줄의 바이트는 건드리지 않는다.

| 입력 | 결과 |
|---|---|
| 없는 id | `그런 주제 노트가 없습니다` — **파일을 만들지 않는다.** 새 주제는 `note_new_topic` |
| 날짜 노트 id (`2026-08-05-0802`) | `날짜 노트에는 덧붙이지 않습니다` |
| 줄바꿈(`\n`·`\r`)이 든 body | `한 줄만 붙입니다` — 조용히 걷어내지 않는다. 여러 줄은 나눠 부른다 |
| 심볼릭 링크·비정규 파일 | `주제 노트가 아닙니다` — 링크를 따라가 바깥 파일에 붙지 않는다 |

### note_list — 최근순 목록

`limit`(기본 20) · `month`(예 `2026-07`).
한 건 = id(=시각) · `context` · **본문 첫 줄**. 대화 메모는 구분선을 건너뛰고 첫 실제 발언을 보여준다.

**두 묶음으로 나뉜다** — 주제 노트가 위, 날짜 노트가 아래. 빈 묶음은 머리글째 생략된다.

```
■ 주제 노트

2026-08-05-표현교정  (정황 없음)
                   피하기: "각 항목은 같은 세 걸음으로 돕니다" → 권장: "각 항목은 같은 세 단계로 진행됩니다"

■ 날짜 노트

2026-07-28-1544  notepad MCP 설계 대화 중
                 mcp 서버가 대화 원문 찾아주는 버튼이 있어야지

(날짜 노트 전체 24장 중 20장)
```

- **`limit`은 날짜 노트에만 걸린다.** 주제 노트는 수가 적고 계속 자라는 장이라 전량 보여준다.
- **`month`도 날짜 노트에만 걸린다.** 월을 지정해도 주제 노트는 그대로 나온다.

### note_read — 한 장 전문

`id`(예 `2026-07-28-1544`, `2026-08-05-표현교정`). 파일 경로도 같이 반환 — yazi·에디터로 바로 열 수 있다.
심볼릭 링크가 걸린 자리는 따라가지 않고 거부한다.

### note_search — 낱말 검색

`query` · `deep`(기본 false) · `limit`.
결과 형식이 `note_list`와 같아 목록→펼침 두 걸음이 그대로 이어진다.
`deep`이면 대화 기록 원본까지 훑고, 히트한 **파일·줄**을 돌려주어 그대로 `note_add_conversation`에 넘길 수 있다.

### note_source — 대화 원문 되살리기 버튼

`id` · `before`(기본 0) · `after`(기본 0) · `include_thinking`.
메모의 `transcript`·`lines`를 따라가 그때 대화를 되살린다. "더 위에서부터"는 `before`를 키워 다시 부른다.
대화 파일이 사라졌거나 출처가 비었으면 **그 사실을 알린다** — 조용히 빈 결과를 주지 않는다.

## 진단

| 증상 | 원인·조치 |
|---|---|
| `transcript`·`lines`가 빈 채로 저장됨 | `CLAUDE_CODE_SESSION_ID`가 없는 환경. 서버는 **추정하지 않고 비운다**(틀린 참조가 더 나쁘므로). stderr 로그 확인 |
| `note_source`가 "대화 파일을 찾을 수 없습니다" | 보존 기간(`cleanupPeriodDays`, 현재 1825일=5년) 경과했거나 다른 머신에서 만든 메모 |
| MCP가 안 붙음 | 세션 재시작 필요. 급하면 stdio 직접 호출: `printf '...JSON-RPC...' \| node .claude/tools/notepad-mcp/server.mjs` |
| 목록 첫 줄이 구분선으로 뜸 | `SEP_RE` 정규식이 구분선을 못 걸러낸 것. 구분선 형식(하이픈 20개)이 바뀌었는지 확인 |
