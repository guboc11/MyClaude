# notepad MCP — USAGE

> 사용 장면 11종. 설계 이유는 [DESIGN.md](DESIGN.md), 도구 인자·진단은 `.claude/tools/notepad-mcp/MANUAL.md`.

## 한 줄 사용법

**"노트에 메모해줘"** 로 적고, **"노트 보여줘"** 로 훑고, **"원문 보여줘"** 로 그때 대화를 되살린다.
"기억해줘"는 노트가 아니라 메모리다.

---

## ① 받아쓰기 — 문구를 직접 불러줄 때

> **사용자:** "무료 영역에 결제 UI 붙이지 않는다" 이거 노트에 적어줘
>
> **클로드:** *(note_add)* 적었습니다 — 2026-07-28-1610

```
---
created: 2026-07-28 16:10
context: 가격정책 논의 중
transcript: 21006ad2-….jsonl
lines: 428
---

무료 영역에 결제 UI 붙이지 않는다
```

에이전트가 손댄 것은 `context` 한 줄뿐. 나머지 세 칸은 서버가 채우고, 본문은 불러준 그대로다.

## ② 가리키기 — 방금 쓴 내 글을 "이거"라고 할 때

> **사용자:** (한참 쓰다가) …제목이 있으니까 어색하고 없어도 이상하고 아..
> 일단 이거 메모해줘
>
> **클로드:** *(note_add)* 적었습니다 — 2026-07-28-1544

"이거"의 범위를 잡는 것이 에이전트가 하는 유일한 판단이다. 라벨은 아무것도 붙지 않는다.

## ③ 대화 통째로 — "지금까지 ○○ 얘기한 거 메모해줘"

> **사용자:** 지금까지 제목 때려치자고 한 얘기 메모해줘
>
> **클로드:** *(note_add_conversation from=381 to=399)* 적었습니다 — 2026-07-28-1552 (사용자 3 · 클로드 2)

```
-------------------- 사용자 (381줄) --------------------
아 '출구에서-분류하기'? 개빡치네 갑자기...

-------------------- 클로드 (388줄) --------------------
이해했습니다. 한 문장으로 하면 — 적을 때 해석하면 화나고...
```

여기서 '알잘딱'은 **어디부터 어디까지 뜰지 줄 범위를 정하는 것**이다. 담기는 것은 여전히 원문 그대로다.

## ④ 빈 종이 — 직접 쓰고 싶을 때

> **사용자:** 메모 하나 만들어줘
>
> **클로드:** *(note_add, body 없음)* 빈 메모를 만들었습니다 — `.claude/mcp-notepad/2026-07/2026-07-28-1620.md`

frontmatter 네 칸만 있는 파일이 생긴다. 터미널에서 긴 글을 불러주기 번거로울 때 에디터로 직접 쓴다.

## ⑤ 훑어보기

> **사용자:** 노트 보여줘
>
> **클로드:** *(note_list)*
> ```
> 2026-07-28-1626  notepad MCP 설계 대화 중 — 사용자 말과 클로드 해석의 구분
>                  사용자의 말인지 클로드가 사용자의 지시로 자기의 해석을 적은 것인지 구분만 하고 싶어
>
> 2026-07-28-1552  notepad MCP 설계 대화 중 — 제목·키워드를 버리기로 한 대목
>                  아 '출구에서-분류하기'? 개빡치네 갑자기. 아 메모 노트패드 갑자기 짜치네.
>
> 2026-07-28-1544  notepad MCP 설계 대화 중
>                  mcp 서버가 대화 원문 찾아주는 버튼이 있어야지
> ```

제목 자리에 사용자 말이 들어간다. 훑다가 **자기 말을 보고 알아본다.**
대화 메모도 구분선이 아니라 첫 실제 발언이 뜬다.

## ⑥ 원문 버튼

> **사용자:** 세 번째 거, 그때 무슨 얘기 중이었는지 원문 보여줘
>
> **클로드:** *(note_source id=2026-07-28-1544)*
> ```
> 21006ad2-….jsonl 381-381줄  (사용자 1 · 클로드 0)
> -------------------- 사용자 (381줄) --------------------
> 아 '출구에서-분류하기'? 개빡치네 갑자기. …
> ```
>
> **사용자:** 좀 더 위에서부터
>
> **클로드:** *(note_source before=10)*
> ```
> 21006ad2-….jsonl 371-381줄  (사용자 1 · 클로드 2)
> ```

메모는 가볍게 두고 무거운 원문은 필요할 때만 불러온다. 대화 메모에서는 잘려나간 앞뒤를 보는 데 쓴다.

## ⑦ 몇 달 뒤에 찾기

> **사용자:** 결제 UI 관련해서 뭐라고 했었지? 노트 찾아봐
>
> **클로드:** *(note_search "결제")* — 메모 1건

메모에서 안 나오면 `deep`으로 대화 기록 원본까지 훑는다. 히트한 파일·줄이 나오므로 그대로 `note_add_conversation`에 넘겨 뒤늦게 메모로 만들 수 있다.

## ⑧ 계획 직전 리마인드 — 만들려는 이유 그 자체

> **사용자:** 자 이제 구현하자. 그전에 오늘 노트 꺼내서 정리해줘
>
> **클로드:** *(note_list → 관련된 것 note_read)*
> 오늘 노트 셋을 봤습니다. 제목·키워드는 넣지 말 것, 메타는 네 칸 고정, 발췌는 복사하지 말고 참조로 둘 것 — 이 셋이 반복해서 나옵니다.

**여기가 해석이 일어나는 유일한 자리다.** 묶고 요약하고 판단하는 것은 전부 여기서 하고, **그 결과는 파일에 남지 않는다.**
그래서 해석이 틀려도 손해가 없고 다음에 다르게 볼 여지가 남는다.

그리고 이것이 MEMORY.md와 갈리는 지점이다 — **평소엔 컨텍스트를 0 차지하다가, 부르는 순간에만 들어온다.**

## ⑨ 주제로 모으기 — "○○ 리스트 만들자"

> **사용자:** 뭣같은 표현 교정 리스트를 만들어야겠어
>
> **클로드:** *(note_new_topic topic="표현교정")* 만들었습니다 — 2026-08-05-표현교정

날짜 노트가 **그 순간을 찍고 끝나는 것**이라면, 주제 노트는 **줄이 계속 쌓이는 장**이다.
파일은 `.claude/mcp-notepad/2026-08-05-표현교정.md` — 월 폴더가 아니라 notepad 루트에 바로 놓인다.
날짜는 서버가 붙이고 **만든 날로 고정**이다. 나중에 줄이 스무 개 붙어도 파일명은 안 바뀐다.

이름이 곧 정체라 같은 이름을 두 번 부르면 튕긴다 — 덮어쓰지도, 뒤에 번호를 붙이지도 않는다.

## ⑩ 리스트에 한 줄 더 — "그것도 추가해"

> **사용자:** "패널이 갈립니다"도 리스트에 추가해줘
>
> **클로드:** *(note_append id=2026-08-05-표현교정)* 붙였습니다 — 2026-08-05-표현교정

```
피하기: "벽돌 4장" → 권장: "섹션 4장"
피하기: "패널이 갈립니다" → 권장: "여기랑 옆 패널은 별개입니다"  (08-05 09:22)
```

줄 끝의 `(MM-DD HH:MM)`이 **언제 들어왔는지**를 남긴다. 없으면 나중에 "이건 언제 왜 들어왔지"를 못 따라간다.

> **표현교정 노트의 작성 관례** — 한 줄에 한 쌍, 왼쪽이 피하기, 오른쪽이 권장, 정확한 표현은 큰따옴표, 방향은 `→`,
> 시각은 서버가 끝에 붙인다. 이건 **이 주제 노트의 관례일 뿐**이고 `note_append`의 body 형식이나
> 다른 주제 노트를 강제하지 않는다 — body는 무엇이든 한 줄이면 그대로 들어간다.

**붙이기지 고치기가 아니다.** 기존 줄과 frontmatter는 한 글자도 건드리지 않는다.
한 번에 한 줄이라 줄바꿈이 든 내용은 튕긴다 — 여러 줄은 나눠 부른다.
날짜 노트에는 못 붙인다. 찍힌 순간에 뒤늦게 덧대지 않는다.

## 하지 않는 것

| | 이유 |
|---|---|
| 제목·키워드·태그 자동 생성 | 의미 주장이라 사용자 말 위에 해석을 덮어쓴다 |
| 발췌 사본 저장 | 잘라내는 순간 이미 가공이다. `transcript`+`lines` 참조만 둔다 |
| 해석을 파일에 저장 | 명시 요청 시에만. 그때도 구분선을 달고 들어간다 |
| 메모 수정·삭제 도구 | md 파일이라 사용자가 직접 고친다. 한 번 적힌 것은 지우지 않는다. `note_append`는 붙이기지 고치기가 아니다 |
| 주제별 하위 폴더 | 아직 안 만든다. 루트에 쌓아두고 많아지면 그때 묶는다 (2026-08-05 결정) |
| 날짜 노트에 덧붙이기 | 그 순간을 찍고 끝난 것이다. `note_append`는 주제 노트에만 |
| 세션 추정 | `CLAUDE_CODE_SESSION_ID`가 없으면 비운다. 틀린 참조가 빈 칸보다 나쁘다 |
