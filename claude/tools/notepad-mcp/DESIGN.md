## 1. 무엇을 만드는가

대화 중 스치는 생각을 붙잡아 두는 **사람용 메모장**이다. 에이전트는 주인이 아니라 **관리인**이다.

`MEMORY.md`와의 관계가 이 도구의 존재 이유다.

| | MEMORY.md | notepad |
|---|---|---|
| 방식 | push — 매 세션 자동 상주 | **pull — 부를 때만 등장** |
| 컨텍스트 | 항상 차지 | **평소 0** |
| 영향 | 클로드 사고를 계속 물들임 | 부른 순간에만 |
| 자리 | 항상 알아야 할 것 | **저장은 하되 상시 영향은 싫은 것** |

어휘로 갈린다. **"기억해줘" → MEMORY / "노트에 적어줘·메모해줘" → notepad.**
이 구분은 도구 설명(description)에 부정 규칙까지 넣어 심는다 → **설정 없이도 동작**하고, `CLAUDE.md`에 한 줄 넣으면 더 단단해진다.

## 2. 설계 원칙

### 2-1. 입구에서 분류하지 않는다

메모장이 죽는 가장 흔한 이유는 **캡처 시점의 마찰**이다. "이거 임시야 영구야?", "카테고리 뭐야?"를 적는 순간에 물으면 흐름이 끊기고, 그건 이 도구의 존재 이유를 정면으로 배반한다.

그래서 **제목·키워드·태그·카테고리를 전부 두지 않는다.**

특히 제목은 단순한 라벨이 아니라 **"이 메모는 무엇에 관한 것이다"라는 의미 주장**이다. 사용자가 방금 쓴 자기 말 위에 에이전트가 뜻을 정해 덮어쓰는 행위이므로, 내 말인데 남이 해석한 결과가 남는다.

반면 `context`("notepad MCP 설계 대화 중")는 허용한다. **정황**(언제 어디서 있었던 일이다)이지 **의미 주장**(무슨 뜻이다)이 아니기 때문이다.

> **정황은 적어도 되고, 의미는 적으면 안 된다.**

### 2-2. 표시 없는 텍스트는 절대 클로드가 쓴 것이 아니다

침묵이 곧 "사용자 말"이라는 보증이다. 클로드가 보탠 것은 반드시 구분선으로 자기를 밝힌다.

덩어리는 세 종류다.

| 덩어리 | 표시 | 정체 |
|---|---|---|
| 사용자 말 | **없음** | 준 텍스트 그대로 |
| 대화에서 인용 | `-------------------- 사용자 (381줄) --------------------` | 실제로 오간 말 |
| 클로드가 새로 쓴 것 | `-------------------- 클로드 해석 --------------------` | 지시받아 지금 쓴 것 |

**줄 번호 유무가 인용과 창작을 가른다.** 번호가 있으면 되짚어 확인할 수 있는 실제 발언이고, 없으면 클로드가 방금 지어낸 문장이다.

구분선은 **ASCII 하이픈 20개**를 쓴다. 사용자가 직접 편집할 때 키보드로 칠 수 있어야 하기 때문이다(박스 문자 `─`는 이 이유로 폐기). `##` 헤딩은 본문에 들어있는 마크다운 헤딩과 섞이므로 쓰지 않는다.
`사용자`/`클로드`는 둘 다 세 글자라 구분선 길이가 맞아떨어진다.

### 2-3. 발췌를 복사하지 않고 참조한다

메모에는 대화 원문을 복사해 넣지 않고, `transcript`(대화 파일명) + `lines`(줄 범위)만 적는다.

- **사본은 뜨는 순간 이미 한 번 가공된 것**이다 — 범위를 자르는 행위 자체가 편집이다. 참조는 원본을 가리키기만 하므로 **가공될 여지가 0**이다.
- 발췌 범위를 얼마나 잡을지 고민할 필요가 없다. 나중에 얼마든지 넓혀 읽을 수 있다.
- 메모 파일이 가벼워 yazi로 훑기 좋다. (대화는 이미 저장돼 있는데 또 복사하는 것은 중복이다)

**한계:** 대화 기록은 `cleanupPeriodDays`가 지나면 삭제된다. 이 머신은 **1825일(5년)로 설정**했다(기존 180일). 0은 검증 오류로 거부되므로 "영구 보존" 설정은 존재하지 않는다.
5년 뒤 원본이 사라지면 메모에는 사용자 말·`context`가 남고 원문 되살리기만 불가능해진다. 그때 오래된 메모만 골라 사본을 뜨면 되므로 지금 대비하지 않는다.

### 2-4. 삭제 없음 / 사람이 직접 고칠 수 있음

한 번 기록된 것은 지우지 않는다. 그리고 그냥 md 파일이므로 yazi·에디터로 직접 편집할 수 있다.
**수정·삭제 도구를 두지 않는 이유가 이것이다** — 내 노트에 내가 펜을 대는 데 허락이 필요하면 안 된다. 서버는 읽을 때마다 파일을 다시 읽으므로 손 편집이 자동 반영된다.

### 2-5. 해석은 꺼낼 때, 파일에 남기지 않는다

묶기·요약·판단은 전부 **회수 시점**에 하고 휘발시킨다. 파일에 박히지 않으므로 해석이 틀려도 손해가 없고, 나중에 다르게 볼 여지가 남는다.

예외는 **사용자가 명시적으로 지시했을 때**뿐이다("네 정리도 붙여줘"). 그때도 §2-2에 따라 표시를 달고 들어간다.

## 3. 메모 형식

### 3-1. 파일 위치

```
.claude/notepad/2026-07/2026-07-28-1544.md   날짜 노트 — 월 폴더 안
.claude/notepad/2026-08-05-표현교정.md         주제 노트 — 루트에 바로
```

- **날짜 노트만** 월별 폴더로 나눈다 (연 수천 장 규모, §6 참조 — 나누는 비용은 0).
  주제 노트는 수가 적고 이름이 곧 정체라 나눌 이유가 없어 루트에 그대로 둔다
- **날짜 노트의** 파일명은 **시각만**. 제목이 없으므로 지어낼 일도, 나중에 파일명이 흔들릴 일도 없다.
  주제 노트는 `{만든 날}-{주제}.md`이고, 그 날짜는 만든 날로 고정이라 역시 흔들리지 않는다
- `.gitignore`에 `.claude/notepad/` 추가 (`.claude/tasks/` 옆) — 폴더 단위라 루트 주제 노트도 함께 무시된다

**두 종류로 갈라진 이유 (2026-08-05 추가)**

날짜 노트는 **한 장이 한 순간**이다. 그래서 이름이 시각이고, 다 쓰면 끝이다.
그런데 "뭣같은 표현 교정 리스트"처럼 **한 주제로 줄이 계속 쌓이는 것**은 이 틀에 안 맞는다.
날짜 노트로 만들면 리스트가 스무 장에 흩어지고, 어느 것이 최신인지 알 수 없다.

| | 날짜 노트 | 주제 노트 |
|---|---|---|
| 한 장의 뜻 | 한 순간 | 한 주제 |
| 이름 | `{시각}.md` | `{만든 날}-{주제}.md` — 날짜는 만든 날로 고정 |
| 자리 | 월 폴더 | notepad 루트 |
| 자라는가 | 안 자란다 | 자란다 (`note_append`) |

**주제별 하위 폴더는 아직 두지 않는다.** 루트에 쌓아두고 수가 늘면 그때 묶는다 —
지금 나누면 어떤 축으로 나눌지 근거 없이 정하게 된다.

### 3-2. frontmatter — 네 칸 고정

```yaml
---
created: 2026-07-28 15:44
context: notepad MCP 설계 대화 중
transcript: 21006ad2-76fa-43c1-bc7b-2a67fd9f67a4.jsonl
lines: 381
---
```

- **상단**에 둔다. 본문이 길어져도 메타는 항상 같은 자리에 있고, yazi 미리보기에서 네 줄만 지나면 본문이다
- 값이 없어도 **칸은 사라지지 않는다** (받아쓰기 메모는 `transcript`·`lines`가 빔)
- `lines`는 한 줄(`381`)이든 범위(`381-399`)든 같은 칸
- **에이전트가 채우는 것은 `context` 하나뿐.** 나머지 셋은 서버가 자동으로 채운다

### 3-3. 본문 — 세 유형

**① 사용자가 준 텍스트** (`2026-07-28-1544.md`)

```
mcp 서버가 대화 원문 찾아주는 버튼이 있어야지
아 그래 내가 yazi 켜서 읽기도 편해야해
제목이 있긴 있어야 하는데 있으니까 어색하고 없어도 뭔가 이상하고 아..
```

**② 대화 파싱본** (`2026-07-28-1552.md`)

```
-------------------- 사용자 (381줄) --------------------
아 '출구에서-분류하기'? 개빡치네 갑자기...

-------------------- 클로드 (388줄) --------------------
이해했습니다. 한 문장으로 하면 — 적을 때 해석하면 화나고...
```

**③ 섞인 것** (`2026-07-28-1626.md`)

```
사용자의 말인지 클로드가 사용자의 지시로 자기의 해석을 적은 것인지 구분만 하고 싶어

-------------------- 클로드 해석 --------------------
표시 없는 텍스트는 사용자의 말, 클로드가 쓴 것에는 반드시 표시가 붙는다.
```

## 4. 도구

### 적기

**`note_add`** — 사용자가 준 텍스트를 그대로 저장
- 입력: `body`(본문), `context`, `agent_note`(선택 — 있으면 `클로드 해석` 덩어리로 붙음)
- `body` 없이 부르면 **빈 종이**가 만들어지고 경로만 반환 (에디터로 직접 쓰는 경우)
- 반환: 영수증 한 줄 + 파일 경로

**`note_add_conversation`** — 줄 범위를 받아 대화를 파싱해 저장
- 입력: `from`, `to`, `context`
- 서브에이전트(`isSidechain`)·도구 결과·`<system-reminder>` 등을 걸러내고 사람이 읽는 발언만 남긴다
- 도구 호출은 `[도구: Bash]` 한 줄로 축약. **thinking은 기본 제외**(옵션으로 포함 가능)

### 주제 노트 (2026-08-05 추가)

**`note_new_topic`** — 주제 노트 새로 만들기
- 입력: `topic`(필수), `body`, `context`. 날짜는 **서버가 붙인다** — 사람이 적으면 어긋난다
- 이름이 곧 정체라 같은 이름 둘을 허용하지 않는다. `wx` 플래그로 만들어 경쟁 상황에서도 덮어쓰지 않는다
- 이름은 조용히 고치지 않는다. 앞뒤 공백·경로 구분자·제어문자는 **거부**한다
  (부른 이름과 다른 파일이 생기는 쪽이 오류보다 나쁘다)

**`note_append`** — 주제 노트 끝에 한 줄 잇기
- 입력: `id`(필수), `body`(필수, **한 줄**)
- 파싱해서 다시 쓰지 않고 파일 끝에만 잇는다 → frontmatter와 기존 줄의 바이트가 구조적으로 보존된다
- 붙는 줄 끝에 `(MM-DD HH:MM)`. **출처(transcript·lines)는 남기지 않는다** — 파일 하나에 출처가
  여럿이라 frontmatter에 못 넣고, 줄 옆에 붙이면 리스트가 읽히지 않는다. 줄마다 시각만 남겨도 충분하다
- 날짜 노트 id는 거부한다(§2-4의 "찍힌 것은 그대로 둔다"와 같은 결)
- **이것은 수정 도구가 아니다.** 붙이기만 하고, 이미 적힌 줄에는 여전히 손대지 못한다

### 꺼내기

**`note_list`** — 최근순 목록
- 출력 한 건 = 시각 · `context` · **본문 첫 줄**
- 제목 자리에 사용자 말이 들어가는 셈. 훑다가 **자기 말을 보고 알아본다**
- **두 묶음으로 나뉜다** — 주제 노트가 위, 날짜 노트가 아래.
  `limit`·`month`는 날짜 노트에만 걸린다. 주제 노트는 수가 적고 계속 자라는 장이라 전량 보인다

**`note_read`** — 한 장 전문 + 파일 경로 (yazi로 바로 열 수 있게)

**`note_search`** — 낱말 검색
- 기본은 메모 파일만. `deep`이면 그 프로젝트의 대화 기록(jsonl)까지 훑는다
- 억지 키워드를 만들지 않는 근거: 본문과 원본이 곧 검색 대상이다

### 원문

**`note_source`** — "대화 원문 찾아주는 버튼"
- 입력: `id`, `before`/`after`(앞뒤로 더 볼 범위)
- `transcript`·`lines`를 따라가 그때 대화를 되살린다
- 텍스트 메모는 "그때 무슨 얘기 중이었나", 대화 메모는 "잘려나간 앞뒤"가 나온다

### 두지 않는 것

수정·삭제(→ §2-4), 태그·상태·연결·색인 나무·백그라운드 정비(→ 쓰면서 필요해지면), 글로벌 메모(→ 프로젝트별로 먼저),
주제별 하위 폴더(→ 수가 늘면 그때).

`note_append`가 생겼어도 **수정·삭제 도구는 여전히 없다.** 붙이는 것과 고치는 것은 다르다.

## 5. 구현 방식

`prototype-mcp`의 관례를 그대로 따른다.

- `.claude/tools/notepad-mcp/server.mjs` — **단일 파일, 의존성 0**(Node 표준 모듈만), JSON-RPC 직접 처리
- `.claude/tools/notepad-mcp/MANUAL.md` — 매뉴얼
- `.mcp.json` 등록:
  ```json
  "notepad": { "type": "stdio", "command": "node", "args": [".claude/tools/notepad-mcp/server.mjs"] }
  ```

**판단은 서버가 아니라 에이전트가 한다.** 서버는 파일을 쓰고 읽는 단순한 물건이고, "발췌 범위를 어디까지 잡을까" 같은 판단은 에이전트 몫이다. 그 규칙은 **도구 설명**에 심는다.

`note_add` 설명에 들어갈 것:

> "노트에 메모해줘", "이거 메모해줘"일 때 쓴다. **"기억해줘"는 이 도구가 아니다**(메모리 담당).
> **제목을 붙이지 않는다. 키워드를 만들지 않는다.** 사용자 말을 한 글자도 고치지 않는다.
> `agent_note`는 사용자가 명시적으로 요청했을 때만 채운다. 평가("좋은 생각이다")가 아니라 사실만.
> 저장 후 영수증 한 줄만 말하고 대화를 이어간다.

### 5-1. 서버가 현재 위치를 어떻게 아는가

`created`·`transcript`·`lines`는 서버가 채운다. 에이전트는 지금 몇 번째 줄인지 모르고, 알아내려면 대화 파일을 읽어야 해서 비싸다.

**폴더** — `~/.claude/projects/` 아래, cwd의 **영숫자 아닌 모든 문자를 `-`로 바꾼** 이름.
실측 확정(2026-07-28): 표본 20건 전수 일치. `/`만 바꾸는 규칙은 경로에 `.`이 있으면 깨진다
(`.claude/worktrees/…` 5건에서 `--claude`가 나와야 하는데 `-.claude`가 됨).
표본에 `_`·공백이 없어 그 문자들은 미검증이므로, 슬러그로 못 찾으면 각 폴더의 `cwd` 필드를 훑는 폴백을 둔다.

**현재 세션** — `CLAUDE_CODE_SESSION_ID` 환경변수가 가리키는 `{sid}.jsonl`. **다른 방법을 쓰지 않는다.**

> 초기 설계는 "가장 최근 수정된 jsonl"로 추정했으나 **실측에서 깨졌다.** 패널 여러 개가 동시에 도는 것이
> 정상 운영 형태라 남이 방금 쓴 파일이 잡힌다 (2026-07-28 게이트 2: 다른 패널의 세션과 그 대화가 잡힘).
> 틀린 참조는 `note_source`를 망가뜨린다 — **"발췌 대신 참조"라는 설계의 뿌리가 무너진다.**
> 그래서 추정 폴백을 두지 않는다. 세션 ID를 못 얻으면 `transcript`·`lines`를 **비운다.**
> 빈 칸은 정직하지만, 남의 대화를 가리키는 메모는 오염이다.

**줄 번호** — 그 파일의 마지막 사용자 텍스트 줄. 에이전트가 명시적으로 넘기면 그것이 우선.

## 7. 폐기된 안과 그 이유

| 폐기안 | 이유 |
|---|---|
| **제목·한줄요약** | 의미 주장이라 사용자 말 위에 해석을 덮어씀. 목록에서 알아보는 것은 **본문 첫 줄**이 대신한다 |
| **키워드 자동 추출** | 발췌·본문에 이미 낱말이 있어 중복. 넓게 깔면 검색이 노이즈가 되고, 무엇보다 "지멋대로 해석"이 파일에 박힘 |
| **발췌 사본 저장** | 참조가 원칙(가공 0)에 더 충실. 사본은 범위를 자르는 순간 이미 편집이다 |
| **박스 문자 구분선(`─`)** | 사용자가 직접 편집할 때 키보드로 칠 수 없음 |
| **`##` 헤딩 구분** | 본문에 들어있는 마크다운 헤딩과 섞임 |
| **열림/닫힘 상태·숨김** | 쓰면서 불편해질 때 붙인다. 기본 목록이 최근순이면 당장 급하지 않음 |
| **계층 색인·백그라운드 정비** | 만 단위에서 필요해질 수 있으나, 지금 만들면 과설계. 목록→펼침 두 걸음으로 상당 부분 버틴다 |
