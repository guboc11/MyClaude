# reminder(MCP) — 매뉴얼

## 이름

**reminder** — 이 세션에만 리마인드를 켜두고, 매 턴 컨텍스트에 다시 넣어주는 MCP

## 형식

```
reminder_on      (label | text | file | group, name?)
reminder_off     (name?)
reminder_set     (label, text | file, remove?)
reminder_group   (name, add? | remove? | delete?)
reminder_always  (label | text | file | group | off?)
reminder_list    (all?)
```

## 설명

규칙을 한 번 말해두면 몇 턴 뒤에는 묻힌다. 컨텍스트가 길어질수록 앞에서 한 말은
뒤에 온 것들에 밀린다. 이 도구는 켜둔 리마인드를 **매 사용자 메시지마다 다시** 컨텍스트에
넣어, 묻히지 않게 한다.

**이 도구는 혼자 일하지 않는다.** MCP 서버는 불릴 때만 말할 수 있어서, 도구를 안 부르는
구간에는 아무것도 못 한다. 그래서 짝이 되는 **UserPromptSubmit 훅**(`hook.mjs`)이 매 턴
실행되며 대신 말한다. 서버는 파일을 놓고, 훅은 그 파일을 읽는다. 둘은 서로를 부르지 않는다.

```
reminder_on  →  파일 하나 생성  →  (매 턴) 훅이 읽어서 출력  →  컨텍스트에 주입
reminder_off →  파일 삭제        →  (매 턴) 훅이 읽을 게 없음  →  침묵
```

**세션 격리가 이 도구의 핵심이다.** 훅 등록은 프로젝트 단위라 이 레포의 모든 세션에서
훅이 실행된다. 그것은 피할 수 없다. 대신 훅은 자기 `session_id` 폴더만 보고, 없으면
아무것도 출력하지 않는다. 출력이 없으면 컨텍스트에 아무것도 안 들어간다.
**전부 실행되고 대부분 침묵**이 정확한 표현이다.

세션 id는 에이전트가 넘기지 않는다. 서버가 `CLAUDE_CODE_SESSION_ID` 로 채운다.
손으로 넘기게 하면 남의 세션에 잘못 꽂는 실수가 가능하지만, 서버가 채우면 그 실수 자체가
불가능하다. *부탁이 아니라 구조로 막는다.*

## 쓰는 순서

```
① reminder_set{label:"…", text:"…"}   자주 쓰는 리마인드를 프리셋으로 등록 (한 번만)
② reminder_on{label:"…"}              이 세션에 켬 → 다음 턴부터 매 턴 주입
   … 일이 진행된다. 매 턴 리마인드가 앞에 붙는다 …
③ reminder_off{name:"…"}              끔 → 다음 턴부터 침묵
```

프리셋 없이 즉석으로 켜려면 ①을 건너뛰고 `reminder_on{text:"…"}`.

## 도구

### reminder_on(label | text | file | group, name?)

이 세션에 리마인드를 켠다. **다음** 사용자 메시지부터 주입된다(켜는 그 턴의 훅은 이미
지나갔으므로 한 턴 뒤부터).

| 인자 | 타입 | 설명 |
|---|---|---|
| label | string | `reminder_set` 으로 등록해둔 프리셋 이름 |
| text | string | 즉석 문구. 준 그대로 저장 |
| file | string | 프로젝트 루트 기준 상대경로. **매 턴 새로 읽는다** |
| group | string | `reminder_group` 으로 만든 그룹. 안의 프리셋이 한꺼번에 켜진다 |
| name | string | 표시 이름(선택). `[REMINDER:이름]` 에 쓰인다 |

**넷 중 정확히 하나만** 받는다. 인자 이름 자체가 구분이다.

```
reminder_on{label: "lint"}                               프리셋 켜기
reminder_on{text: "빌드 전에 lint 먼저"}                  즉석 문구 켜기
reminder_on{file: "_CRAFT_GUIDE/DB_MIGRATIONS.md"}   파일 참조 켜기
reminder_on{group: "coding"}                             그룹 통째로 켜기
```

0개거나 2개 이상이면 위 네 형태를 그대로 보여주며 튕긴다.
없는 label 이면 있는 프리셋 목록을 붙여 튕긴다. 없는 파일도 튕긴다.

`label` 과 `file` 은 **참조로 저장된다**(`@label:이름` / `@경로`). 그래서 프리셋이나
대상 파일을 나중에 고치면 다음 턴부터 고친 내용이 나간다. 다시 켤 필요가 없다.

> 주의: `file` 은 그 파일 **전문**을 매 턴 주입한다. 긴 문서를 켜두면 매 턴 컨텍스트를
> 그만큼 먹는다. 규칙 요약본을 따로 두고 그것을 가리키는 편이 낫다.

### reminder_off(name?)

끈다. 다음 턴부터 주입되지 않는다.
`name` 을 생략하면 **지금 켜진 목록만** 보여준다(무엇을 끌지 고를 때).
켜져 있지 않은 이름을 주면 켜진 것 목록을 붙여 튕긴다.

프리셋은 지우지 않는다. 점등과 프리셋은 다른 층이다.

### reminder_set(label, text | file, remove?)

프리셋을 등록·수정·삭제한다. **프로젝트 공용**이라 세션과 무관하게 남는다.
`text` 또는 `file` 중 하나를 준다. 지우려면 `remove: true`.

세션 id가 없어도 동작한다 — 프리셋은 세션에 속하지 않기 때문이다.

프리셋을 지워도 그것을 켜둔 세션의 점등 파일은 남는다. 그 세션에는 다음 턴에
`(프리셋을 찾을 수 없음: 이름)` 이 주입된다. 침묵보다 낫다고 판단한 동작이다.

### reminder_group(name, add? | remove? | delete?)

여러 프리셋을 한 번에 켜기 위한 **메타데이터**다. 프리셋 이름의 목록일 뿐,
그 자체로 주입되는 내용은 갖지 않는다.

| 인자 | 하는 일 |
|---|---|
| `name` 만 | 그 그룹 내용 보기. 없어진 프리셋은 `← 프리셋 없음` 으로 표시 |
| `add` | 프리셋 넣기. 그룹이 없으면 그때 만들어진다. 문자열 또는 배열 |
| `remove` | 프리셋 빼기. 문자열 또는 배열 |
| `delete: true` | 그룹 삭제. 켜둔 세션의 리마인드는 그대로 |

`add` 와 `remove` 를 동시에 주면 튕긴다. 한 번에 한 가지만 한다.

**없는 프리셋을 `add` 하면 튕긴다.** 죽은 이름이 그룹에 앉는 것을 켤 때가 아니라
넣을 때 막는다 — 그래야 고치기 쉽다.

**켤 때 사라진 프리셋이 있으면 있는 것만 켜고 알린다.** 나머지가 멀쩡하므로
전부 실패시키지 않는다.

```
켰습니다 — coding (2개)
  codegraph, db-rules
  건너뜀: lint (프리셋이 없습니다)
```

**그룹 통째로 끄기는 없다.** 켜는 순간 개별 파일로 펼쳐져서 "이것이 그 그룹이었다"는
흔적이 남지 않기 때문이다. 흔적을 남기려면 개별로 켠 것과 형태가 달라져 훅까지 영향이
간다. 훅을 안 건드린다는 이점이 더 크다고 판단했다. 끄는 것은 `reminder_off` 로 하나씩.

### reminder_always(label | text | file | group | off?)

**모든 세션에 항상** 나가는 영구 리마인드. 세션을 가리지 않는다.

| 부르는 법 | 하는 일 |
|---|---|
| `label`·`text`·`file`·`group` 중 하나 | 켠다. 인자 뜻은 `reminder_on` 과 같다 |
| `off: "이름"` | 끈다 |
| 인자 없음 | 지금 항상 켜져 있는 것 보기 |

**`reminder_on` 과 인자가 거의 같은데도 도구를 분리한 이유는 무게가 다르기 때문이다.**
`reminder_on` 은 내 세션에만 영향을 주지만 이쪽은 이 레포에서 도는 **모든 사람의 모든
세션**에 나간다. 인자 하나 차이(`always: true`)로 갈리면 실수로 전체에 켜질 수 있어서
이름 자체를 분리했다.

이것은 이 도구의 격리 원칙("켜지 않은 세션은 조용") **밖**에 있다. 팀 공통 규칙처럼
정말로 항상 필요한 것에만 쓴다. `reminder_list` 가 항상 맨 위에 보여주는 것은
켜둔 채 잊는 것을 막기 위해서다.

같은 이름이 영구와 세션 양쪽에 켜져 있으면 한 번만 나간다(영구 쪽이 이긴다).

### reminder_list(all?)

이 세션에 켜진 것과 등록된 프리셋·그룹 목록을 함께 보여준다.
`all: true` 를 주면 다른 세션에 무엇이 켜져 있는지까지 보여준다.

## 이름 규칙

프리셋·그룹 이름은 **영문 소문자 + 숫자 + 하이픈**만 쓴다 (`codegraph`, `db-rules`, `coding`).
파일명이자 도구 인자이자 `[REMINDER:이름]` 표시라, 경로·인코딩 문제의 여지를 처음부터
없앤다. 어긋나면 저장하지 않고 튕긴다.

## 저장 레이아웃

```
<project>/.claude/mcp-reminders/
  labels/{label}.md                   프리셋 (프로젝트 공용)
  groups/{group}.md                   그룹. 프리셋 이름을 줄마다 하나씩 (프로젝트 공용)
  always/{name}.md                    영구 점등 — 모든 세션에 나감
  sessions/{session_id}/{name}.md     점등 상태 (켜기=생성, 끄기=삭제)
```

**한 장 = 한 파일**인 이유: 서로 다른 프로세스(다른 MCP 서버·다른 세션·훅)가 한 JSON을
같이 고치면, 나중에 쓴 쪽이 먼저 쓴 쪽을 덮어 항목이 소리 없이 사라지거나 반쯤 쓰인
파일이 남는다. 파일 단위로 나누면 만든 쪽만 건드리고 훅은 읽기만 하므로 충돌이 없다.
파일 이름이 곧 "누가 켰나"의 기록이기도 하다.

`.gitignore` 에 등재됨 — 리마인드는 git에 안 올라간다.

## 파일 내용 규칙 (훅이 읽는 문법)

| 내용 | 뜻 |
|---|---|
| `@label:이름` | `labels/이름.md` 를 읽어 한 번 더 푼다 (그 안이 `@경로` 면 그것까지) |
| `@경로` | 루트 기준 상대경로 파일을 매 턴 새로 읽는다 |
| 그 외 | 문구 그대로 |

프리셋 안에서 다시 `@label:` 이 나오면 따라가지 않는다(루프 차단).

## 훅 동작 (hook.mjs)

`.claude/settings.json` 의 `UserPromptSubmit` 에 등록되어 매 턴 실행된다.

1. 프로젝트 루트는 스크립트 자기 위치에서 역산한다(cwd 비의존 — 훅의 실행 디렉토리를
   우리가 통제하지 않으므로).
2. `always/*.md` 를 먼저 읽어 출력한다. 세션을 가리지 않으므로 `session_id` 없이도 나간다.
3. stdin JSON에서 `session_id` 를 읽어 `sessions/{session_id}/*.md` 를 이어서 출력한다:
   `[REMINDER:{name}] {내용}`. 앞에서 이미 낸 이름은 건너뛴다.
4. 켜진 게 없으면 출력 0바이트.

**절대 조건 세 가지** — 이 훅은 이 레포의 모든 세션 매 턴에 실행되므로:

- 어떤 경우에도 `exit 0`. 리마인드가 깨져도 사용자 메시지를 막으면 안 된다.
- 켜진 게 없으면 출력 0바이트. 남의 세션에 흔적을 남기지 않는다.
- 에러는 stderr 로만. stderr 는 컨텍스트에 주입되지 않는다.

참조가 깨지면 침묵하는 대신 `(참조 파일을 찾을 수 없음: 경로)` 를 주입한다.
"켜져 있다고 믿는데 안 나가는 상태"가 침묵보다 위험하다.

## 다른 MCP 에서 켜고 싶을 때

이 도구는 다른 MCP 서버와 코드를 공유하지 않는다. 서버끼리는 서로를 부를 수 없기 때문이다.

대신 그쪽 도구 응답 문구에 "이제 `reminder_on{label:"…"}` 을 부르세요" 라고 적어두면,
에이전트가 그것을 읽고 이어 부른다. 연결 규칙이 코드가 아니라 도구 응답 문구에 산다.

이 방식은 구조가 아니라 에이전트 행동에 의존한다. 빼먹으면 리마인드가 안 켜진다.
호출이 대화에 다 보이므로 빼먹으면 드러난다는 것이 유일한 안전장치다.

## 실측으로 확인된 것 (2026-07-29)

- 훅 stdin 의 `session_id` 와 서버의 `CLAUDE_CODE_SESSION_ID` 는 **같은 값**이다.
  (한 턴의 훅 덤프에 세 세션이 찍혔고, 그중 이 세션 값이 환경변수와 일치)
- 훅을 등록하면 **이미 떠 있는 세션에도 즉시** 적용된다(세션 시작 시 스냅샷이 아니다).
- 켜지 않은 다른 세션들에서도 훅은 실행되지만 침묵한다 — 격리가 실전에서 동작한다.
- `@label:` 참조는 실제 주입 경로에서 풀린다. 프리셋을 고치면 세션 파일을 건드리지 않아도
  다음 턴부터 고친 내용이 나간다.
- 훅 stdin 에는 `session_id` 외에 `transcript_path`, `cwd`, `prompt_id`,
  `permission_mode`, `prompt` 도 온다(추후 확장 여지).

## 구현 메모

무의존성 Node 단일 파일(`fs`, `path`, `url` 만), stdio JSON-RPC 2.0.
`notepad-mcp` · `task-mcp` 골격 재사용.

서버 배선은 `import.meta.url === argv[1]` 가드 안에 있고 내부 함수를 export 한다 —
테스트가 `toolOn` 등을 직접 불러 검증할 수 있게 하기 위함.

설계 원본: 같은 폴더 `DESIGN.md`
