# Next Session — 세션 인수인계 스킬

## 왜 이 스킬이 필요한가

에이전트의 컨텍스트가 많이 차면 맥락을 제대로 못 잡거나, 사용자의 지시를 상기하지 못하거나,
작업물 품질이 떨어진다. 이때 clear를 하고 새 세션으로 넘어가는 게 효과적인데,
문제는 세션이 바뀌면 그동안 쌓인 맥락이 전부 날아간다는 것이다.

이 스킬은 현재 세션의 맥락을 "다음 세션이 읽으면 바로 상황 파악이 되는 온보딩 메시지"로 정리해준다.
사용자는 이 메시지를 복사해서 새 세션에 붙여넣기만 하면 된다.

## 핵심 원칙

### 맥락 보존이 최우선

간결함보다 맥락 보존이 중요하다. 다음 세션의 에이전트가 이 메시지만 읽고도
"처음부터 함께 있었던 것처럼" 상황을 파악할 수 있어야 한다.
빠진 맥락은 다음 세션에서 실수나 방향 오류로 이어지므로,
필요한 내용을 줄이는 것보다 빠뜨리지 않는 것이 더 중요하다.

단, 파일 내용 자체를 본문에 복붙하지 않는다. 파일 경로를 알려주고 "이 파일을 읽어라"고 안내한다.

### 행동 지시 금지

온보딩 메시지는 상태 전달이지 작업 지시가 아니다.
"~를 해라", "~부터 시작해라" 같은 행동 지시를 넣지 않는다.
다음 세션에서 뭘 할지는 사용자가 결정한다.

**좋은 예:** "도메인 모델 리팩토링이 진행 중이고, Wedding 애그리거트 분리까지 완료했다. HostParticipation 분리는 아직 시작하지 않았다."
**나쁜 예:** "다음으로 HostParticipation 분리를 진행해주세요."

## 온보딩 메시지에 포함할 내용

### 0. 세션 ID

현재 세션의 `.jsonl` 파일명(= 세션 ID)을 찾아서 포함한다.

**찾는 방법:**
1. `ls -lt ~/.claude/projects/{프로젝트-경로}/*.jsonl | head -3`으로 최근 수정 파일 후보를 좁힌다.
2. 현재 대화에서만 존재하는 고유 텍스트(예: 사용자 첫 메시지)로 `rg -l "고유 텍스트" 후보파일들`을 실행해 확정한다.

**온보딩 메시지에 넣는 형태:**
`이전 세션 ID: {uuid}`

### 1. 이번 세션에서 한 작업

무엇을 했는지 구체적으로 서술한다. 어떤 파일을 만들었고, 어떤 파일을 수정했고,
어떤 논의를 했는지. 결과물이 있으면 경로를 명시한다.

### 2. 사용자 피드백

사용자가 작업 중에 준 피드백, 수정 요청, 방향 전환을 기록한다.
"사용자가 ~라고 했다"는 식으로 원문 뉘앙스를 살린다.
이건 다음 세션에서 같은 실수를 반복하지 않기 위해 중요하다.

### 3. 교훈 (LESSON)

이번 세션에서 알게 된 것. 기술적 발견, 도메인 이해, 에이전트가 실수했던 것과 그 원인 등.

### 4. 현재 상태

작업이 어디까지 진행됐는지. 완료된 것, 진행 중인 것, 아직 시작하지 않은 것.
다음 작업이 무엇을 기다리고 있는지 (사용자 결정 대기, 외부 의존성, 선행 작업 완료 필요 등).

### 5. 참고 파일 및 맥락

다음 세션에서 읽어야 할 파일 경로와, 각 파일이 왜 중요한지 간단한 설명.
프로젝트의 주요 규칙이나 제약사항 중 이번 세션에서 특별히 부각된 것이 있으면 언급한다.

## 출력 형식

메시지는 사용자가 그대로 복사해서 붙여넣을 수 있는 형태로 작성한다.
코드블록 등으로 감싸서 복사하기 쉽게 만든다.

```
[이전 세션 온보딩]
세션 ID: {uuid}

(여기에 온보딩 내용)
```

## 하지 말 것

- **행동 지시를 넣지 않는다.** 상태 전달만.
- **파일 내용을 본문에 복붙하지 않는다.** 경로만 안내하고 "읽어라"고 한다.
- **이번 세션 대화를 통째로 붙이지 않는다.** 정리된 형태로 전달한다.
- **사용자 확인 없이 자동으로 clear하지 않는다.** 메시지를 보여주고 사용자가 복사한 뒤 직접 clear한다.
