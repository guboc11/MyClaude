# Feedback — 사용자 피드백 기록 스킬

## 왜 이 스킬이 필요한가

에이전트는 나름의 판단으로 방향을 잡고 작업한다. 그런데 사용자의 기준은 에이전트가
추론할 수 있는 것보다 훨씬 구체적이고 미묘하다. 에이전트가 A로 갔는데 사용자가 A'을
원하는 경우, 혹은 에이전트가 A로 갔는데 사용자 기준에선 그게 틀린 경우 — 이 차이를
기록해두지 않으면 다음 세션에서도 같은 어긋남이 반복된다.

LESSON(/reflect)이 "에이전트가 객관적으로 실수한 것"을 기록한다면,
FEEDBACK은 "사용자의 의도·판단·기준과 어긋난 것"을 기록한다.
사용자 기준에서 틀린 것도, 방향이 미묘하게 다른 것도 모두 여기에 해당한다.

## LESSON과의 차이

| | LESSON (/reflect) | FEEDBACK (/feedback) |
|---|---|---|
| 대상 | 객관적 실수 — 규칙 위반, 버그, 프로세스 오류 | 사용자 기준 — 방향, 디테일, 판단 차이. 틀린 것 포함 |
| 저장 위치 | 실수 발생 지점 근처 LESSON.md (분산) | 프로젝트 루트 FEEDBACK.md (단일 파일) |
| 톤 | "이거 하지 마라" | "사용자는 이걸 이렇게 원한다" |
| 코드 주석 | 해당 코드 근처에 추가 | 추가하지 않음 |

## 호출 방식

### 1. `/feedback` (단독 호출)

인자 없이 호출하면, 에이전트가 현재 대화를 되돌아보며 사용자가 방향을 수정하거나
디테일을 잡아준 부분을 스스로 찾아서 기록한다.

흐름:
1. 대화에서 피드백에 해당하는 부분을 식별
2. 사용자에게 보여주고 확인 요청
3. 승인받으면 FEEDBACK.md에 기록

### 2. `/feedback {내용}` (인자 포함 호출)

사용자가 직접 피드백 내용을 전달한 경우. 사용자가 "이건 피드백이다"라고 명시한 것이므로
에이전트는 그 내용을 존중해서 기록한다. 사용자가 말한 내용을 더 강조하거나,
사용자의 의도를 정확히 반영하는 데 집중한다.

흐름:
1. 사용자가 전달한 내용을 정리
2. 사용자에게 보여주고 확인 요청
3. 승인받으면 FEEDBACK.md에 기록

## FEEDBACK.md 작성 규칙

프로젝트 루트의 `FEEDBACK.md` 하나에 계속 append한다. 기존 내용을 덮어쓰지 않는다.
파일이 없으면 새로 생성한다.

각 피드백 항목의 기본 구조:

```markdown
## [2026-04-07 14:30] 피드백 제목

**맥락**: 어떤 작업/논의에서 어긋남이 발생했는지
**에이전트가 한 것**: 에이전트가 어떤 방향/판단으로 갔는지
**사용자가 원한 것**: 사용자가 실제로 원했던 방향/디테일
**기억할 것**: 다음에 비슷한 상황에서 어떻게 해야 하는지
```

톤은 다음 세션의 에이전트에게 말하듯이.
"사용자는 ~를 이렇게 원한다", "~할 때는 ~방향으로 가라", "사용자 기준에서 ~는 틀린 거다."

포맷은 위 구조를 기본으로 하되, 내용에 따라 에이전트 재량으로 조절해도 된다.
핵심은 다음 세션의 에이전트가 읽었을 때 사용자의 기준을 파악할 수 있느냐다.

## 메모리 업데이트

### Claude Code 환경
FEEDBACK.md에 기록한 뒤, Claude Code의 메모리 시스템(`~/.claude/`)에도 반영한다.
프로젝트 전반에 걸친 피드백이면 CLAUDE.md에, 특정 도메인 관련이면 해당 위치에.

### Cowork 환경
FEEDBACK.md만 수정하면 된다. 별도 메모리 업데이트 불필요.

## 하지 말 것

- **변명하지 않는다.** "그때는 정보가 부족해서..." 같은 변명을 기록하지 않는다.
  사용자가 원한 것이 무엇인지에 초점을 맞춘다.
- **기존 FEEDBACK.md를 덮어쓰지 않는다.** 항상 append한다.
- **사용자 확인 없이 기록하지 않는다.** 무엇을 기록할지 먼저 보여주고 승인받는다.
- **LESSON과 혼동하지 않는다.** 객관적 실수는 /reflect로, 방향·기준 차이는 /feedback으로.
  애매하면 사용자에게 물어본다.
- **코드 주석을 추가하지 않는다.** FEEDBACK은 프로젝트 방향성 기록이지 코드 경고가 아니다.
