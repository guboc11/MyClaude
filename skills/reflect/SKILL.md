# Reflect — 교훈 기록 스킬

## 왜 이 스킬이 필요한가

에이전트는 세션이 바뀌면 이전 세션에서 혼났던 걸 모른다. 사용자가 같은 지적을 매번 반복해야 하는 건
사용자에게도, 에이전트에게도 비효율적이다. 이 스킬은 실수와 지적을 파일 시스템에 영구적으로 남겨서,
다음 세션의 에이전트가 해당 파일이나 폴더를 작업할 때 자연스럽게 교훈을 읽고 같은 실수를 피하게 한다.

## 흐름

### 1단계: 무엇을 잘못했는지 파악

현재 대화 컨텍스트를 돌아보며 에이전트가 실수한 것, 사용자에게 지적받은 것,
방향을 잘못 잡았던 것을 식별한다.

사용자에게 정리한 내용을 보여주고 확인을 받는다:
```
이번 세션에서 이런 부분들이 지적됐어요:
- [지적 내용 1]
- [지적 내용 2]

이 내용들을 기록할까요? 빠진 게 있으면 말씀해주세요.
```

### 2단계: LESSON.md 배치 위치 결정

교훈은 실수가 발생한 지점 가까이에 배치한다.

- **단일 파일 수정 중 지적**: 해당 파일이 있는 폴더에 `LESSON.md` 생성/추가
  - 예: `src/domain/Wedding.ts` 수정 중 혼남 → `src/domain/LESSON.md`
- **여러 파일 수정 중 지적**: 해당 파일들의 공통 부모 폴더에 `LESSON.md` 생성/추가
  - 예: `src/domain/Wedding.ts`와 `src/domain/GiftMoney.ts` 둘 다 관련 → `src/domain/LESSON.md`
- **프로젝트 전반적인 지적** (코딩 스타일, 작업 방식 등): 프로젝트 루트 `LESSON.md`

이미 해당 위치에 LESSON.md가 있으면 새 교훈을 append한다. 기존 내용을 덮어쓰지 않는다.

### 3단계: LESSON.md 작성

각 교훈은 다음 내용을 포함한다:

```markdown
## [2026-04-07 14:30] 교훈 제목

**상황**: 어떤 작업을 하다가 어떤 실수를 했는지
**지적**: 사용자가 뭐라고 했는지 (원문 뉘앙스 유지)
**원인**: 왜 이런 실수가 발생했는지
**교훈**: 다음에는 어떻게 해야 하는지
```

날짜와 시간은 반드시 `[YYYY-MM-DD HH:MM]` 형식으로 기록한다.

톤은 다음 세션의 에이전트에게 말하듯이. "이 파일 수정할 때 ~하지 마라. 사용자가 ~를 싫어한다."

### 4단계: 코드 주석 추가

코드를 수정하다 지적받은 경우, 해당 코드 근처에 주석으로 경고를 남긴다.
다음 세션의 에이전트가 이 코드를 읽을 때 바로 눈에 띄어야 한다.

```typescript
// ⚠️ LESSON: 이 로직을 변경할 때 축의금 슬롯 단위 격리 규칙을 반드시 지켜야 한다.
// Groom이 GroomFather의 축의금을 볼 수 없다. (2026-04-07 지적)
```

주석은 짧고 명확하게. 상세 내용은 가까운 LESSON.md에 있으니 참조 경로를 달아도 좋다.

### 5단계: LESSON_INDEX.md 업데이트

프로젝트 루트의 `LESSON_INDEX.md`에 새 교훈의 링크를 추가한다.
파일이 없으면 새로 생성한다.

```markdown
# Lesson Index

| 날짜 | 시간 | 위치 | 요약 |
|------|------|------|------|
| 2026-04-07 | 14:30 | [src/domain/LESSON.md](src/domain/LESSON.md) | 축의금 슬롯 격리 규칙 위반 |
| 2026-04-07 | 15:10 | [src/api/LESSON.md](src/api/LESSON.md) | API 응답 형식 임의 변경 금지 |
```

## 메모리 업데이트

### Claude Code 환경
LESSON.md에 기록한 뒤, Claude Code의 메모리 시스템(`~/.claude/`)에도 반영한다.
프로젝트 전반적인 교훈이면 CLAUDE.md에, 특정 도메인 관련이면 해당 위치에.

### Cowork 환경
LESSON.md만 수정하면 된다. 별도 메모리 업데이트 불필요.

## 하지 말 것

- **변명하지 않는다.** "컨텍스트가 부족해서...", "이전 지시가 모호해서..." 같은 변명을 기록하지 않는다.
  원인 분석은 하되, 다음에 어떻게 해야 하는지에 초점을 맞춘다.
- **기존 LESSON.md를 덮어쓰지 않는다.** 항상 append한다.
- **사용자 확인 없이 기록하지 않는다.** 무엇을 기록할지 먼저 보여주고 승인받는다.
