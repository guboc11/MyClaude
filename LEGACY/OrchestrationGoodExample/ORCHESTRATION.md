# Orchestration

## 웨딩메모리북이란

결혼식에서 발생한 모든 추억을 하나의 디지털 결과물로 엮은 것. 하객들이 보낸 축하 메시지, 현장에서 찍은 사진, 디스플레이에 띄워졌던 이미지, 참석자 목록 등이 하나의 웹 페이지에 아름답게 구성된다. 결혼식이 끝난 뒤 호스트(신랑·신부)가 간직하는 결혼식의 기록이자, 하객들과 공유할 수 있는 추억의 매개체다.

## 목적

예쁘고 아름답고 감성적인 웨딩메모리북을 만든다. 어떤 디자인이 정답인지 아직 모르기 때문에, Claude 오케스트레이터가 에이전트들을 투입해 자율적으로 루프를 돌며 다양한 시안을 빠르게 찍어낸다. 사용자가 충분하다고 판단하면 루프를 종료한다. 다양한 시도는 수단이지 목적이 아니다 — 최종 목적은 결혼식의 감동을 담아낼 수 있는 아름다운 결과물을 찾는 것이다.

## 원칙

1. **감성 품질이 최우선** — 모든 판단 기준은 "이걸 받은 신랑·신부가 감동할 수 있는가"다. 기술적 완성도, 코드 품질은 그 다음이다.
2. **진짜 다른 시도를 한다** — 색상 톤만 바꾸거나 레이아웃 순서만 뒤집는 건 다른 시도가 아니다. 버전 간에 구조·무드·타이포그래피·인터랙션 중 최소 두 축 이상이 근본적으로 달라야 한다. 이전 버전과 겹치는 레퍼런스·무드는 사용하지 않는다.
3. **누적 학습** — 각 버전은 독립적 시도이되, 이전 리뷰의 피드백은 반영한다. "다른 걸 시도하되, 배운 건 가져간다."
4. **자율 진행, 품질 게이트** — 루프는 사람 개입 없이 돌지만, 리뷰 단계가 감성 품질의 하한선을 보장한다. 기준 미달이면 수정 후 통과시킨다.
5. **실패 허용** — 에러가 나면 재시도하고, 반복 실패하면 스킵한다. 하나의 실패가 전체 루프를 멈추지 않는다.

## 구조

```
idle → research → planning → dev → review → done → idle (반복)
```

구체화 흐름: `Seed + Research → DESIGN.md → PLAN.md → DEV`. 각 단계는 이전 단계의 산출물에 종속되며, 추상에서 구체로 점진적으로 구체화된다.

- **research**: 이번 싸이클의 방향성(seed)을 받아, 외부에서 더 나은 결과물들을 찾아보고 배우는 단계. 웹 검색, 레퍼런스 이미지 수집, 디자인 트렌드 조사 등을 통해 기획의 재료를 확보한다. 갖고 있는 지식만으로 기획하는 것은 절대 금지 — 반드시 새로 조사한 외부 자료를 기반으로 한다. 산출물: research 폴더 — REFERENCES.md(참고한 URL 등 출처 모음), {리서치 주제}.md(개별 리서치 내용), INSIGHTS.md(리서치에서 뽑은 인사이트 모음), CONCLUSION.md(전체를 종합한 최종 결론).
- **planning**: 리서치 결과와 이전 리뷰 피드백을 바탕으로 이번 버전을 기획한다. 산출물: DESIGN.md(추상적 디자인 기획) + PLAN.md(수치·레이아웃·개발 방향이 구체적으로 명시된 계획. 개발자가 이것만 보고 구현해도 방향이 크게 어긋나지 않을 수준).
- **dev**: PLAN.md에 따라 실제 결과물을 구현한다. PLAN.md에 명시된 수치·레이아웃·구조를 충실히 따르되, 감성 품질을 위한 디테일은 DESIGN.md를 참고한다. 산출물: 구현 파일.
- **review (최종 통합 리뷰)**: DESIGN.md·PLAN.md·구현물을 종합적으로 평가하고, 필요하면 수정한다. 산출물: 평가 점수 + 다음 버전을 위한 제안.

## 공통 규칙

- **단계별 리뷰**: research, planning, dev 각 단계는 다음 단계로 넘어가기 전에 자체 리뷰를 거친다. 산출물이 해당 단계의 목적에 부합하는지 확인하고, 미달이면 수정 후 통과시킨다.
- **최종 통합 리뷰**: 모든 단계가 끝난 뒤 전체 싸이클을 관통하는 리뷰를 수행한다. 리서치부터 구현까지의 일관성, 감성 품질, DESIGN.md 대비 구현 충실도를 종합 평가한다.
