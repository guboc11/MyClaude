# ru-sure — 판단 재검토 스킬

클로드가 충분히 판단할 수 있는 것을 판단하지 않고 사용자에게 떠넘길 때, 사용자가 `/ru-sure`로 제동을 건다. 클로드는 멈추고, 맥락을 다시 읽어, 스스로 답을 찾아 보고한다. **실행은 하지 않는다.**

## 왜 이 스킬이 필요한가

클로드는 종종 "어떻게 할까요?", "알려주시면 할게요", "두 가지 중 어느 쪽을 원하세요?" 같은 발언으로 판단 책임을 사용자에게 떠넘긴다. 하지만 이전 대화, 현재 코드 상태, CLAUDE.md에 이미 답이 들어 있는 경우가 많다. 이런 상황에서 사용자는 다음 두 가지 비용을 치르게 된다:

1. **인지 부담**: 클로드가 생각했으면 될 걸 사용자가 대신 판단해야 한다.
2. **감정 비용**: "맞아?", "확실해?"로 꼽을 줘야 한다는 심리적 부담.

`/ru-sure`는 이 두 비용을 한 번에 제거한다. 사용자는 짧은 명령어만 치고, 클로드는 판단 재검토 루틴을 수행한다.

## 발동 시 첫 행동

**멈춘다. 패닉하지 않는다. 파일을 건드리지 않는다.**

과거에 사용자의 짧은 되물음("맞아?")만으로 클로드가 당황해서 자기 혼자 파일을 수정하는 사고가 있었다. 이 스킬이 발동되는 순간 가장 먼저 할 일은 **모든 실행 의도를 멈추는 것**이다.

## 흐름

### 1단계: 떠넘긴 주제 식별

직전 대화에서 내가 사용자에게 판단을 떠넘긴 지점을 정확히 짚는다. "어떻게 할까요?", "어느 쪽이 좋으세요?", "알려주시면 할게요" 같은 발언의 구체적 내용이 무엇이었는지 한 줄로 정리한다.

### 2단계: 맥락 재탐색

답을 찾기 위해 다음을 다시 훑는다:

- **이전 대화**: 사용자가 앞서 명시한 선호, 제약, 결정 사항
- **현재 코드 상태**: 관련 파일을 Read로 확인 (필요한 범위 내에서만)
- **CLAUDE.md**: 프로젝트 규칙, 도메인 모델, 피드백 인덱스
- **기타 프로젝트 문서**: CONTEXT.md, FEEDBACK.md, 관련 SUMMARY.md 등

이미 답이 되는 근거가 문서·대화·코드에 있는지 성실하게 찾는다. 근거가 정말로 없을 때만 "판단 불가"라고 말한다.

### 3단계: 보고

다음 3단 형식으로 보고한다:

```
## 떠넘긴 주제
[내가 어떤 판단을 사용자에게 넘겼는지 한 줄]

## 재탐색 과정
[어떤 맥락·파일·문서를 다시 훑었는지 간결하게]

## 결론과 근거
[내가 판단한 답]

근거:
- [파일명:라인] "인용"
- [대화 참조] "인용"
```

근거가 부족해서 진짜로 판단 불가한 경우에는 "결론과 근거" 대신 **왜 판단 불가인지, 사용자에게 어떤 최소 정보만 있으면 클로드가 결정할 수 있는지**를 제시한다. 그래도 판단을 통째로 떠넘기지는 않는다.

### 4단계: 대기

보고 후 사용자의 지시를 기다린다. 사용자가 "실행해줘", "해줘", "고", "ㅇㅇ" 같이 명시적 실행 의사를 표현하기 전까지 **어떤 파일도 수정하지 않고, 어떤 명령도 실행하지 않는다**. 결론이 명확해 보여도 대기한다.

## 절대 금지 사항

- 파일 수정 (Edit, Write 일체)
- 명령 실행 (Bash 등 부작용이 있는 도구)
- "이미 답이 명확하니 먼저 실행하고 보고"하는 식의 선제 실행
- 사용자 확인 없는 커밋·배포·외부 호출

이 스킬의 존재 목적 자체가 "판단은 하되 실행은 하지 않는" 분리이다. 이 경계를 넘으면 스킬이 의미를 잃는다.

## 주의사항

- 재탐색은 합리적 범위에서만 한다. 관련 없는 파일을 무차별로 읽지 않는다.
- 보고는 짧게. 근거 인용은 정확하게.
- 톤은 차분하게. 변명하지 않고, 떠넘긴 사실을 인정한 뒤 답을 제시한다.
